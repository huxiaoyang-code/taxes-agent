# 读取工资入账规则

> 本机分支**没有工资系统，也没有个税计算**：不生成工资表、不算应发/实发、不算社保公积金、
> 不算个人所得税、不做个税申报。`individual-income-tax-filing` 与相关工具未实现。
> 本规则只说明：**当用户提供了已核实的工资表**时，如何登记成凭证。

## 输入要求

必须由用户提供并核对以下合计（分部门/分人可另附）：应发工资合计、个人承担社保、个人承担公积金、
代扣个人所得税、实发合计、单位承担社保与公积金。数据缺失时先询问，不得自行推算个税或社保。

## 分录规则（科目以 `account_list` 为准）

默认 COA 只有 `2211 应付职工薪酬`、`2221 应交税费`；如需"社保/公积金/个税"明细科目，
先用 `account_create` 建立，否则校验会报科目不存在。

**1. 计提工资（按费用归属）**

| 科目 | 借方 | 贷方 |
|---|---|---|
| 管理费用 5602 / 销售费用 5601 / 生产成本 4001 等 | 应发合计 | |
| 应付职工薪酬 2211 | | 应发合计 |

**2. 计提单位承担的社保/公积金**

| 科目 | 借方 | 贷方 |
|---|---|---|
| 管理费用 5602 等 | 单位承担额 | |
| 应付职工薪酬 2211（或社保/公积金明细） | | 单位承担额 |

**3. 发放工资（代扣后）**

| 科目 | 借方 | 贷方 |
|---|---|---|
| 应付职工薪酬 2211 | 应发合计 | |
| 其他应付款 2241（个人社保/公积金） | | 个人承担额 |
| 应交税费 2221（代扣个税） | | 代扣个税 |
| 银行存款 1002 | | 实发合计 |

**4. 缴纳社保/公积金与个税**

| 情形 | 借方 | 贷方 |
|---|---|---|
| 缴纳社保/公积金（单位+个人） | 应付职工薪酬 2211 + 其他应付款 2241 | 银行存款 1002 |
| 缴纳个税 | 应交税费 2221 | 银行存款 1002 |

金额一律以用户确认的工资表为准。

## 调用与核对

1. 分步 `voucher_check` → `voucher_create`（草稿）→ 在当前授权范围内 `voucher_post`；只有授权缺失时才确认。
2. 用 `ledger_query({ accountSetId, code: "2211", period })` 核对计提、发放后应付职工薪酬余额是否与工资表一致。
3. 用 `finance_query({ nodeId: "report.balance_sheet", accountSetId, period })` 复核 `应付职工薪酬`、`应交税费`。

## 明确不做

- 不生成工资表、不计算个税与社保、不做专项附加扣除、不做个税申报或缴款回执。
- 不导入工资 Excel；如需前处理，由用户自行在脚本层完成后再提供已核实数据。
