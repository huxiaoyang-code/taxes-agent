# 读取发票入账规则

> 本机分支**没有发票数据源**：不采集、不查验、不读取发票明细、不做发票台账。
> `invoice_collect` / `invoice_file` / `invoice.detail` / `invoice.unbooked.*` 均不可用。
> 本规则只说明：**当用户提供了已核实的结构化发票数据**时，如何登记成凭证。

## 输入要求

记账前必须从用户处拿到并核对以下字段；缺任何一项都先询问，不得猜测：

- 发票类型：增值税专用发票 / 普通发票 / 电子发票 / 红字发票；销方还是购方。
- 不含税金额、税率、税额、价税合计（三者应能互相校验，不一致时以用户确认值为准）。
- 可抵扣结论：进项税能否抵扣必须由用户/会计明确核实；本工具**不依据票种或纳税人身份自行判定税法资格**。
- 开票日期、对方名称、商品或服务摘要。

## 分录规则

科目以账套实际科目表为准（`account_list` 查询）。本机默认 COA 只提供 `2221 应交税费` 一个
税金科目，没有 `222101` 等明细；若确需明细，先用 `account_create` 建立子科目，否则
`voucher_check` 会报"科目不存在"。所有金额为不含税/税额/价税合计的确定值，不自行估算税额。

以下按**用户/会计已核实的可抵扣结论**分别给出可抵扣/不可抵扣示例；**不以发票种类或纳税人身份自动推断**。

**采购（经确认进项税额可抵扣）**

| 科目 | 借方 | 贷方 |
|---|---|---|
| 库存商品 1405 / 原材料 1403 / 相关费用 5602 等 | 不含税金额 | |
| 应交税费 2221（进项税额） | 税额 | |
| 应付账款 2202 / 银行存款 1002 | | 价税合计 |

**采购（经确认进项税额不可抵扣）**：价税合计全额计入成本或费用，不拆分进项税。

**销售开具发票**

| 科目 | 借方 | 贷方 |
|---|---|---|
| 应收账款 1122 / 银行存款 1002 | 价税合计 | |
| 主营业务收入 5001 | | 不含税金额 |
| 应交税费 2221（销项税额） | | 税额 |

**红字发票**：按用户提供的红字发票数据冲减对应收入/进项，方向与原分录相反；金额以红字发票为准。
本地不开具红字发票，也不申请红字信息表。

## 调用与核对

1. `voucher_check({ accountSetId, entries })` 确认借贷平衡、科目存在。
2. `voucher_create({ accountSetId, period, voucher_date, summary, entries })` 生成**草稿**。
3. 在当前授权范围内 `voucher_post` 过账；只有授权缺失时才向用户确认。
4. 摘要在凭证里写明发票号码与对方名称，便于人工核对（本地没有发票—凭证关联表）。

返回的凭证对象包含 `id`、`status`、`total_debit`、`total_credit`、`entries`；汇报时原样给出关键字段。

## 明确不做

- 不采集/下载发票原件，不查验真伪，不维护进销项台账，不判断发票是否重复入账。
- 不根据图片/PDF 自动识别发票内容。
- 不判定税法抵扣资格：可抵扣/不可抵扣以用户/会计已核实结论为准，不按票种或纳税人身份推断。
- 不计算应纳税额、不做申报。税率、税额必须以用户提供的已核实数据为准。
