# 读取报销入账规则

> 本机分支**不能解析报销单据**（无 OCR、无附件读取、无审批流）。只能依据用户提供的
> 已核实报销明细记账。原站的附件上传流程**不是**本地已接入的能力，不要据此承诺。

## 输入要求

- 报销人、报销日期、费用归属部门/用途、金额、是否含可抵扣进项税、对应期间。
- 是否已审批：本地没有审批系统。若用户明确声明已审批，按已批准处理；否则生成草稿并请用户确认。
- 缺少用途或金额构成（如差旅费中含可抵扣税额）时先询问。

## 分录规则（科目以 `account_list` 为准）

**直接报销（员工垫付后公司付款）**

| 科目 | 借方 | 贷方 |
|---|---|---|
| 管理费用 5602 / 销售费用 5601 等 | 报销金额（不含可抵扣税额） | |
| 应交税费 2221（进项税额，若有且可抵扣） | 税额 | |
| 银行存款 1002 / 库存现金 1001 | | 价税合计 |

**先挂账再付款**

- 批准报销时：`管理费用/销售费用` 借方，`其他应付款 2241` 贷方。
- 实际付款时：`其他应付款 2241` 借方，`银行存款 1002` 贷方。

**员工借款与还款**

- 借出备用金：`其他应收款 1221` 借方，`银行存款 1002` 贷方。
- 报销冲借款：`管理费用` 借方，`其他应收款 1221` 贷方；差额再通过银行/现金结清。

金额按用户确认值登记，不自行拆分或估算税额。

## 调用与核对

1. `voucher_check` 校验 → `voucher_create` 生成草稿。
2. 在当前授权范围内 `voucher_post` 过账；只有授权缺失时才向用户确认并保留草稿。
3. 用 `finance_query({ nodeId: "report.income_statement", accountSetId, period })` 复核本期费用金额。

## 明确不做

- 不读取/解析报销附件，不做发票—报销关联，不落附件证据链。
- 不执行审批流；不要把"已收到单据"等同于"已审批"。
