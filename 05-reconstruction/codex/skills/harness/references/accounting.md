# 直接核算与凭证

主Agent根据业务选工具，不要求先登记计划或维护运行时任务图。先核实企业、账套、期间和原件覆盖，工具后台检查目标及输入并自动记录。

- 原始业务底稿：`finance_record_contract`读取选中记录合同，再用`finance_workpaper`计算。结果中的库存、分录、报表和issues分别核对；凭证草稿不等于已入账。
- 已有账簿：`finance_query`、`ledger_query`等按真实schema查询；科目、资产、期间和辅助信息仅使用当前可用入口。
- 明确分录：先`voucher_check`核科目、金额和借贷，按实际授权使用`voucher_create`及过账工具。归类及资格仍需业务依据，平衡不证明正确。
- 历史导入：使用`book_import_incremental`等真实入口，先预检，保持原来源及批次身份；见[导入规则](../../legacy-book-import/references/import-rules.md)。
- 正式业务写入：直接业务工具保留既有审计、备份、期间、防重复和人审要求。准备、执行、查询按实际合同，不由Agent伪造确认或绕过业务入口。

采购销售和退货须核数量、价税、批次和原单；销售配送与采购运费区分；往来汇总不能冒充逐笔银行核销。用原件及工具返回的定位核对差异，无法表达的业务列为工具缺口或模型参考，不塞入错误类型强行计算。

报告依次展示金额、凭证/计算和规则，完整调用及原件供深入调查。结果未知先核原身份，不换任务、来源或批次重复写账，见[恢复](recovery.md)。
