# 日常报告与深入核对

适用于本插件所有财税交付。报告面向核对账本的人，内部记录面向排错；显示顺序不会改变后台完整保存。

## 日常报告顺序

1. **账本金额**：企业本机代号、账套、期间、币种和单位；期初、本期发生、期末、税费金额及差额。未知保留未知，不将缺失或null补成0。
2. **凭证与计算结果**：实际工具生成的分录、库存批次、抵扣清单、计算过程和勾稽。区分草稿、已入账、工具结果、模型推导和待核；每个关键金额引用其实际结果。
3. **规则依据**：适用准则/税种、规则来源、条款定位、有效期间、地区及资格事实，解释本期为何这样处理。规则由实际工具查询，不用上游美国示例作为中国政策。

金额展示人民币元、通常两位小数；原生整数转换遵守实际单位。万元、数量和百分比必须明确标注；应纳、计提、实缴与未证实支付分别报告。

## 深入排错顺序

4. **工具调用**：需要调查时展开系统保存的调用编号、工具、版本、时间、输入输出摘要、成功/失败/未知和完整本机结果引用。调用成功不等于业务通过。
5. **输入与原件**：沿结果引用查到本次输入、转换与验证，以及原件页/表/行/字段及摘要。引用匹配只能证明定位与字节对应，不能保证原件真实性或业务语义正确。

直接工具自动留存，不要求 Agent 手工维护事实ID、版本摘要或运行时任务图。完整记录不可因日常报告折叠而省略。不得将真实企业账库、原件、凭据或调用记录提交到Git/PR；只提交代码和合成测试。

## 缺件与更正

具体说明缺什么、影响哪个金额或判断、可接受原始证据及补齐后的核对目标。历史结果保留；资料或规则变化后重新调用受影响工具，比较真实前后差异，不覆写旧日志或改原件凑平。
