# 接手与导入旧账

Codex 负责理解业务、整理资料、请求补件及编制有据的导入输入；现有工具负责校验和写账。客户不需要内部模板、预制分录或算好的税额。先按任务选择必要资料和核验，不把人员陈述、旧系统余额或工具默认值直接当成已核事实。

## 整理与存放

- 原始旧账、凭证附件和人员陈述保留原件及版本；派生输入另存，错误通过修正转换或补充证据处理，不改原件凑平。
- 保存解析代码、记录映射、金额及总分核对、未识别内容和未决问题。原件、派生输入、验证结果与 Harness Store 是本机证据文件；正式账库保存通过业务入口登记的账套、科目、期初、凭证等，不把调查文件全部塞入账库。
- 尚未有真实账套绑定时先在本机整理，不编造 ID 初始化 Harness。绑定后按[资料接入](../harness/references/materials.md)登记来源和事实。真实数据与模型可见内容遵守本次授权及项目数据边界。

## 选择导入入口

先查实际企业身份及现有账套；同一企业只有一个正式账套，显示名称不能代替稳定身份。

- 正常接手优先 `book_import_incremental`：用稳定 `source.system`、`source.enterpriseKey`、`batchId`，支持首次 `mode:"create"` 与已有账套 `mode:"append"`、来源凭证去重和冲突检查。已有同企业账套时使用真实 `accountSetId` 追加；不要先用 `account_set_create` 建空账套，再以 create 模式导入。
- 只需要建立空账套时可用 `account_set_create`；主体、准则、纳税人类型和启用期间须有依据，不依赖兼容默认。
- `legacy_book_import` 保留兼容的一次性新建导入，没有增量批次重放；它也要求显式企业身份，已绑定企业会拒绝新建，不会合法地产生第二个同企业账套。

具体 envelope、内部 JSON/四 CSV、预检与重试见[导入规则](references/import-rules.md)。标准 MCP 可以公布这些工具；宿主是否加载或延迟暴露需实际确认。当前 Pi Harness 扩展未显式暴露上述导入工具，不能假定发现不到就代表后端不存在，也不能绕过业务入口直接写 SQL。

## 预检、落库与接管

`dryRun` 缺省为 true；先检查实际预检的错误、警告、行数、期初和凭证与原始资料的对应关系。缺日期、未知金额、身份或制度未核清时保留缺项，不利用解析器的月初/零值默认制造完整输入。结构与借贷平衡通过不证明业务事实成立。

经所需核验和实际授权后，以同一已核输入显式 `dryRun:false` 写入；保留返回结果。增量导入后查 `book_import_batch` 的来源凭证追踪及当前核验状态，再核对目标账套、科目、期初、凭证明细和相关报表。状态可能变化，预检不预先保证未来写入成功。结果未知时先查询原批次，不能换批次盲重试。

交给 B 前，明确接管截止日/下一期间、已核余额及明细、历史凭证映射、未决问题及其影响、依据版本和实际复核记录。用 `harness_scope_discover` 重新取得真实企业/账套/实例，再按[Harness 入口](../harness/SKILL.md)绑定支持的期间和任务。既有账务需要的期初、检查点和旧凭证映射以所选能力合同及实际 blocker 为准；导入成功不自动完成这些核验。目前没有统一的接管包自动验收工具，不声称整家公司已可接管；未决问题只允许不依赖它的任务继续。

Excel 等资料由宿主选择可用解析方式并验证；仓库 `05-reconstruction/tools/xlsx-to-csv.py` 可辅助处理 `.xlsx`，不保证任意版式或 `.xls` 自动解析。原站附件上传和未实现的 `exec` 工具不是本机导入通道。
