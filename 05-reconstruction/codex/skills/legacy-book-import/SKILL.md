# 接手与导入旧账

主Agent调查和整理原件，工具校验与写账，自动保存实际调用。客户不需要内部模板、预制分录或已算税额。人员陈述和旧系统余额是线索，须核期间、来源和完整性。

## 工作流程

### 1. 清点与核对

原始旧账、凭证附件和陈述只读留存，派生输入另存。核真实企业、准则、期间、科目、期初及原凭证身份；保存转换代码、映射、行数金额检查和未识别项。本机文件可读不代表获准向模型外发真实原值，按本次授权与资料边界处理。

### 2. 选择直接导入

用`account_context`核已绑定企业。正常接手优先`book_import_incremental`：首次`mode:"create"`，已有同企业账套`mode:"append"`，使用稳定来源、企业和批次身份。不要先建空账再create同企业。只需空账套时使用`account_set_create`。

兼容`legacy_book_import`为一次性新建，不具有增量批次恢复语义。格式、四CSV、预检与重试见[导入规则](references/import-rules.md)，客户不需制作这些内部格式。

### 3. 预检与写账

先`dryRun:true`核对实际错误、警告、科目、期初和分录。缺日期或未知金额不得利用解析器月初、零值默认假装齐全。结构和平衡通过不证明原件事实真实。

根据实际授权和需要的核验，以同一已核输入显式`dryRun:false`。结果未知先`book_import_batch`查询原批次，不换身份盲重试。来源或内容变化遵守更正合同，不能覆盖旧批次或直接SQL改账。

### 4. 核对与交付

导入后核真实账套、期初、明细和报表，保存已核基线、接管截止日、历史凭证映射及未决影响。导入成功不等于整企历史验收。后续直接调用账簿、`finance_workpaper`或税费工具，不再初始化Store或登记任务。

按[报告顺序](../harness/references/reporting.md)先列账本金额、凭证/导入结果和规则依据，调用及输入原件供深入核对。原件、正式账库和自动记录分别备份；真实数据、凭据和会话不提交仓库或PR。
