# 接手与历史整理

以“哪些业务可以有依据地接手”为终点，不以文件数量或完整度百分比放行。初次接手没有可信账套时先在本机整理；有账套也需核实其企业身份、期间和来源。

## 调查资料

先盘点实际经营活动、来源系统和预期覆盖期间，再按适用性索取原始导出/扫描件。不要把下表变成所有企业必须一次交齐的清单，也不要仅凭“没有这项业务”判不适用。

| 要核实的事项 | 常用证据与核对 |
|---|---|
| 主体与范围 | 登记及税务信息、经营合同、会计政策、账户清单；核对主体/地区/准则/身份的生效日期 |
| 旧账完整性 | 账套备份或导出、科目及辅助体系、期初、连续科目余额/总明细账、凭证和附件、结账状态；核对期间断档和借贷、总分、跨期勾稽 |
| 销售采购与资金 | 合同/订单、履约/验收/发货、发票、收付款及银行对账；收款、收入、开票和纳税义务分别核查 |
| 往来和成本 | 客商明细、账龄、核销；适用时取得库存收发存、盘点、成本方法和历史结转，核对数量/金额/期间 |
| 资产与人工 | 适用时取得资产卡片、购置/处置和折旧；薪酬、人员及社保等在本机核验，不将明细发给模型 |
| 历史税务 | 认定/备案、历次申报表和回执、完税/缴款、留抵/亏损/预缴等结转依据、通知和未结事项；下载申报信息不等于完整账套 |
| 其他重要事项 | 股东及关联方往来、借款担保、租赁、补贴、诉讼等，以实际业务和异常线索决定范围 |

对每份来源记录本机文件、来源系统/提供人、获取时间、企业/期间、覆盖范围、版本/摘要、页表行字段定位及是否已核。原件只读留存，派生转换另存；保留映射、解析代码、行数/金额校验、未识别项。重复件去重但保留来源，冲突版本不能择一个方便值覆盖。

## 历史核对和修复

1. 从接管截止日倒推所需余额及结转证据。用期初 + 本期发生 = 期末、总账 = 明细/辅助、账面 = 外部对账依据逐层定位差异；公式相等不证明原业务真实。
2. 把差异分为资料缺失、时间口径、科目/主体错误、重复/遗漏、未知原因等。每条关联原业务身份、凭证、期间和原件；不能按差额直接编分录、补日期或补零。
3. 形成可复核更正方案：原因、受影响期间/账表/税种、备选处理、政策依据、预计影响、所需复核与执行入口。历史错账、税务更正、缴款及资料补齐分别处理。
4. 经真实复核和现有授权执行支持的更正，保留原账、前后差异和实际回执。重大前期差错或工具未支持的处理保留待办，不用当期分录冒充历史问题已解决。
5. 按依赖分支交接：缺库存历史成本会阻塞相关成本/利润/税务结论，仍可做不依赖它的已核工作。调查深度覆盖当前任务所需历史，不无限追溯，也不隐去未查期间。

## 接管基线

交付本机版本化基线，至少包括主体及实际账套绑定、接管截止日/下一期间、原件覆盖与未查范围、已核期初/余额及往来/库存/资产/税务结转明细、原凭证身份映射、未决问题及阻塞分支、实际更正与复核记录。声明“可接手的任务”和“仍不能交付的结果”，不写笼统的“全部正确”。

正式导入、查询原批次、受影响业务重算及三类数据备份按 [工具与交接](harness-handoff.md)。导入成功、原件摘要或 `originVerified` 字段均不是接管验收。
