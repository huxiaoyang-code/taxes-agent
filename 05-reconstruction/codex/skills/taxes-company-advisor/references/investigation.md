# 疑点复核与异常应对

疑点来自 B 提醒、历史核对、人员线索或税局通知。先限定要回答的问题；异常指标不直接证明漏税、违法或记账错误。

## 复核路径

1. 保存原通知/疑点及版本，在本机核对对象、期间、事项、正式渠道和回复期限。口头转述与正式通知分开，期限不凭经验猜；临近期限且证据不足时提醒负责人确认办理方式。
2. 对收入、成本、利润、税负或现金异常，先核同一主体、期间、含税/不含税、累计/当期、应纳/实缴等口径，再与可用历史及业务变化比较。同行参考值只能作为调查线索，注明来源和可比性，不能当法定安全线。
3. 对每个候选解释建立“主张 → 支持/反证 → 账/票/银/合同履约/申报定位 → 尚缺证据”。例如收款增加可能是回收旧应收，必须核销关联及原收入/税点，不能仅凭金额相同认定。
4. 先复算能复算的事实，保留不确定项；新证据推翻旧解释时版本化更正。对本机原值的核验仍遵守主技能的数据边界。

## 交付一条可处理的案件

在主技能交付字段基础上，补充：

- **问题与事实**：对方具体疑问、已核事实、存在争议和未查范围。
- **证据目录**：每项证据对应哪一主张，是否原件、覆盖期间及缺口；全文和真实身份只放本机。
- **解释草稿**：逐项回答，区分事实、推断、假设；不能写“完全合规”“已解释清楚”而没有依据。
- **处理选项**：补证、核销/账务更正、重新测算、税务更正或向主管机关核实等；每项列前提、预计影响、期限和需由谁执行。
- **关闭条件**：哪些原件/实际回执证明此问题已解决；回复已发送不等于税务机关已接受，账已改不等于税已更正。

正式回复、补件外发、改账、申报更正和付款使用当前授权及既有受控入口；本技能不会因生成草稿自动发送或执行。不重复索要已有明确授权，但授权范围或目标不明时应先澄清该动作。

## B 回流与再进入

保留原 B task/receipt 的实际身份和版本；调查结果作为新证据或更正方案回流。由既有工具登记来源、更新受影响事实，读取当前状态并按真实依赖重绑重算。保留旧回执/旧复核，不能手工将旧结果改成有效或删除历史。若未接入该类事实/方案，交付本机材料及明确工具缺口，不发明 `risk_resolve` 等入口。
