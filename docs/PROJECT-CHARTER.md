生效日期：2026-10-13。依据用户确认的需求、派工、模型服务使用和自动合并授权制定。用户后续明确指示优先于本章程。

## 目标与边界

把已有逆向证据转化为本机可验收的财税工作台。第一期范围见 [团队实施计划](TEAM-PLAN.md)。全国电子税务局登录和授权信息获取是后续必须实现的目标，本期交付可扩展接口；预留接口不等于已连接全国系统。

产品形态是**本机单用户**工具：一名操作者在自己电脑上运行，面向**多家企业 / 多个账套的批量处理**（批量导入、计提、结转、结账、出报表等）。批量账套不等于多租户——本项目不做 SaaS、多租户、租户权限平台、对外服务或账户体系。只保留本机实际需要的账套数据隔离、操作日志 / 审计留痕、备份恢复与凭据安全。后续任务队列、批量能力均以本机运行为前提，不承诺未实现的批量能力。

功能状态只能依据代码、可重复测试与实际联调证据，区分已实现、仅有接口、待开发。不得把模板、模拟适配器、工具名称或测试假数据当成真实能力。

## 团队与权限

### 多人协作（2026-10-15 用户确认）

- 项目可由**多名人类成员**在各自电脑上协作，每人配自己的本机 Codex（本机管理者）与本机执行员工（pi / Claude Code）。**开发多人不等于产品多租户**：产品仍是本机单用户、可多账套批量。
- 角色按层：**人类成员**决定目标 / 范围并核对本人授权——**跨任务需求范围由用户 / 项目负责人决定，成员只在已分配任务内作常规实现选择**；**成员自己的本机 Codex** 负责拆解、隔离工作区、阅读实际 diff、跑验证、写任务单与 PR 正文、执行 Git / PR / 合并，**不直接补写业务代码 / 测试 / 交付文档**；**执行员工**只做实现与自测，不执行 Git 提交 / 推送 / 合并。
- **目前登记并经项目负责人授权的成员为 `huxiaoyang-code` 与 `xiaoyihaishiaini`**；这两人可独立审查验收自己派出的员工成果并**自动合并自己的 PR**（用户已授权），不需要项目负责人逐 PR 批准，但该授权**不自动扩展到新贡献者**。**GitHub 不允许批准自己账号开的 PR 的正式 review**，本机 Codex 审查是独立于员工的内容审查，**不冒充 GitHub 第二账号批准**。跨成员评审按任务风险 / 共享文件需求安排，不一律强制每 PR 人工批准。
- 同事作为个人私有仓库协作者拥有 **write** 权限即可 push / 开 PR / review / merge，**不要求 admin 权限**、不要求改仓库设置。
- 文件所有权、任务认领、共享同步、合并协调与凭据边界见 [团队协作协议](TEAM-COLLABORATION.md)；任务分配以 GitHub Issue / PR + [任务看板](tasks/README.md) 为远端权威，不以任何单台电脑或聊天为准。最终 RC-6 端到端集成由项目负责人统一协调。

## 什么算一个完整部分

一个部分是可独立说明结果、验证和回退的交付单元，通常对应一个任务及一个 PR。大型任务先拆成多个这样的部分，例如 CORE-A（封账、期初、期间）与 CORE-B（报表、折旧、结转）。单个函数写完或某次测试通过不算阶段完成。

完成条件必须全部满足：范围内实现与文档齐备；管理者阅读实际差异；验收覆盖业务结果和关键失败路径；基于待合并版本测试通过；PR 已合并；交接记录包含可核验的提交和结果。未完成事项明确登记，不能为清空上下文而隐去阻塞或标记完成。

## 总流程

1. **恢复工作**：读取本章程、[阶段状态](handoffs/STATE.md)、本任务交接和相关接口；核实 main、工作区及仍运行的进程，避免重复启动和覆盖未完成成果。
2. **需求与任务单**：写清目标、非目标、依赖、输入输出契约、允许修改文件、验收标准、模型与数据边界。只对真正缺失的关键信息询问用户。
3. **隔离派工**：从已验收共同基线建立 `codex/` 前缀分支和独立 worktree；互不冲突的文件可并行，同一核心文件由一个执行者负责。共享接口先约定，不能各自猜测。
4. **开发与自测**：执行者修改授权文件，用临时数据完成回归测试，提供变更与失败说明。员工不直接修改 main、不自行提交推送或合并。
5. **管理者审查**：核对范围、实际 diff、边界行为和测试质量；独立复现关键场景。发现缺陷退回同一部分修复，未验收不得合并。
6. **PR 验收合并**：更新到最新 main，检查冲突并重跑受影响测试；PR 写明具体问题、结果、测试和限制。管理者按已验证的完整 head SHA 合并，禁止强推 main。将 PR 附到当前任务。
7. **交接归档**：更新阶段状态，记录合并 SHA、PR、测试命令及结果、接口变化、限制、下一部分输入和仍运行进程。交接文档也纳入版本控制；PR 自身的合并 SHA 可在随后的交接提交补录。
8. **清空执行会话，进入下一部分**：结束该部分的本地 agent 会话，使用新进程、新会话和精简任务包开始下一部分；不续用上一部分聊天、不粘贴整段日志。新会话先核对交接与 Git 事实，再开发。

## 上下文重置规则

以“文件与 Git 为长期记忆、会话为临时工作区”。本地 pi 使用 `--no-session`，Claude Code 使用 `--no-session-persistence`；下一部分重新启动进程，不使用 resume/continue。关闭会话不能代替检查退出码，不能遗留重复执行的后台员工。

同一部分审查返工可启动新的修复会话，只传该部分任务单、发现和必要文件；不必等待返工结束才做上下文精简。并行部分分别重置，一个完成不应打断另一个。

Codex 管理会话无法通过仓库代码或工具强制清空当前对话上下文，不能声称已经清空。管理者在每个阶段边界先完成交接，再只依据当前任务包和必要源码继续；如果用户主动开启新的 Codex 对话，新对话按本章程恢复工作。自动压缩上下文不代表阶段完成，也不能丢失用户授权。

新任务包只包含：任务 ID、目标与验收、基线 SHA、文件所有权、依赖契约、必要交接链接、尚未解决事项及有效授权。原始日志保存在忽略目录 `.agent-runs/`，不默认传给下一会话。

## 验收与恢复

会计回归验证金额、平衡、状态和失败后的原子性；MCP 验证真实 stdio 到临时后端链路；税务接口验证未配置状态、会话隔离及异步状态机，实际税局能力必须另有真实授权联调证据。

禁止为通过测试删改旧断言或伪造成功。测试须明确命令、工作目录、结果和基线；后续无相关改动不反复扩大测试。真实运行库、账号和生产会话不得用于自动回归。

中断时记录已完成/未完成、分支和 worktree、进程标识及日志路径。恢复先核实进程与文件，不能把会话失联当作已失败后重复派工。合并后回退通过新的 revert PR，禁止重写 main 历史。冲突或无法验收时保留现场并报告真实状态。
