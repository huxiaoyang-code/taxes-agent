## 2. 判定规则（沿用方案 §4）

- 若真实环境**只有企业列表 / 申报汇总** → **不能完成自动财务闭环**；必须由用户提供本地资料（旧账文件 / 手工录入），系统须**明确标识来源**并显式标记「数据不足」，不得让报表看起来像全部由税局自动取得。
- 任何缺失项一律按「未知」处理：**不补 0、不生成凭证、不推断金额**。
- 生成「可申报文件」≠ 向税局正式提交；报送 / 签章 / 缴款为另行明确操作。

## 3. 第二步（真实登录）执行约定

1. **只由用户在本机可信界面**登录并输入验证码：账号 / 密码 / 验证码 / 扫码**都不进模型、不进日志、不进 Git / PR**。
2. 模型侧只收**安全引用**与**不含真实业务 / 身份原文的状态摘要**；本文件只回写「无原文状态摘要」（可得 / 未知 / 阻塞）。
3. 逐项核对本矩阵：记录**来源、字段、期间、口径、完整度 / 缺失、授权与证据**，无证据的行保持「未知」。
4. 结论二选一：**数据链路成立** 或 **不成立 / 部分成立**（写明只能做到什么）。**无真实配合时先完成第一步并记录第二步为待验证，不假成功。**

## 4. 当前结论

- 真实登录与数据可得性**未验证**；**真实接入 0**。
- 当前引擎**可以生成零数据报表**（无期初 / 无凭证时科目余额为 0），但**这不等于财务闭环完成或可用业务报表**：没有期初 / 凭证等资料，报表只是空表，不能视为可用业务报表。
- 草稿可交付的仅是「人工登录 → 只读识别企业候选 → 建 / 绑**空账套**」；**空账套载入标准科目表，但缺期初 / 凭证等资料，不能视为财务闭环完成或可用业务报表**。
- 自动财务闭环是否成立**取决于第二步结果**；在此之前一律按「未知」，不推进自动财务闭环、不宣称任何税局数据已自动取得。
