# 开发与协作规范

## 范围与分工

- 产品面向中国财税，在本机服务单个操作者。一名操作者可处理多家企业，每家企业一个账套。多企业批处理的范围限于本机，SaaS、多租户和账户权限平台在产品范围外。
- 实现方式遵循用户当前明确指示。开工前确认成员身份、任务范围、依赖和文件所有权。共享文件改动先协调。当前需求、分工、未完项及验收证据统一记在 [Issue](../.github/ISSUE_TEMPLATE/requirement.md) 和 [PR](../.github/pull_request_template.md) 中，避免重复任务单、状态表和长交接。
- 使用隔离 worktree 和 `codex/` 前缀分支，经 PR 整合。保护 `main` 和他人未提交的成果，禁止直接改 `main`、强推或覆写。基线变化后根据实际影响复验。

## 工程与验证

- 从 [中文架构](AGENT-ARCHITECTURE.md) 和 [代码索引](CODE-INDEX.md) 找到实际源码、工具合同及正常入口，依据行为确认能力和覆盖范围。
- 改动 Harness、Agent 工具、Skill 或记忆前，按 [Harness 工程规范](HARNESS-TOOL-DESIGN.md)核对当前官方原文和实际宿主、模型及协议。明确用户可观察结果、采用依据、必要改动与行为验收。官方发布或宿主版本变化影响结论时，重查并复验。
- 从 `06-workbench` 运行 `npm test` 使用[统一入口](../06-workbench/scripts/test-all.mjs)，单组验证按[代码索引](CODE-INDEX.md#tests)选择。自动测试只用合成数据和临时目录，严禁覆盖真实业务库。
- 实施者自测后，由未参与实现的审查者在全新上下文阅读实际 diff，通过正常入口核对必要验证、实际产物与终态。在 Issue / PR 记录工作目录、命令、结果、已审版本和未验证范围。严禁预填通过或冒充 GitHub 第二账号批准。

## 授权与本机数据

- 仅已登记并获负责人授权的 `huxiaoyang-code` 与 `xiaoyihaishiaini` 可自动合并自己已分配范围内的 PR，前提是满足验收、独立审查和整合约束。新成员须另行登记授权。
- 各成员使用自己的 GitHub、Codex 与模型服务凭据。跨电脑经仓库、Issue 和 PR 同步，禁止复制他人的 token、配置、会话或账套数据库。
- 真实账套数据、税务凭据、会话与验证码留在本机可信界面，禁止送往模型服务或写入日志、Git 和 PR。保留账套隔离、审计、备份恢复和凭据安全边界。
- 源码、任务说明和测试错误仅在用户本次明确授权的范围内外发。通用协作规则不授予外部系统权限。禁止绕过沙箱或变更仓库可见性和设置。
