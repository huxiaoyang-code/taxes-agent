### M1 · 已申报期一个项目先取到真实结果

**输入**：用户明确登录完成后的有效企业绑定；已观察的申报查询来源；本地可核项目 / 所属期。PR #35 仍是独立 Draft，不自动并入本包；如需复用，先独立审查其必要实现并核实际 head，不能整包带入未知状态。

**实施**：

1. 优先核已观察 `DescribeSbmxcx2` 的固定 9 个 body 字段 / 13 个行字段契约及业务成功、只读语义和参数来源；当前生产 `QUERY_PATHS` 未支持，不能直接宣称可调用。所有运行参数仅由本机可信层从实际已核来源构造，不接模型任意 URL / body。
2. 分别建立门户 6 行与查询页另 6 行的结果账册；期间集合已不同，不能因行数相等自动合并。核稳定业务键、申报版本、更正 / 作废关系与重复语义；未知 id / 时间戳 / 内容 hash 不能擅自定义稳定业务身份。
3. 在现有 query / live 边界内实现经核来源的有界分页、企业 / 期间绑定及私有持久结果；未到终点记 partial。禁止将原值透传 MCP 或错误文本。
4. 用现有 MCP → HTTP → Agent → 后端两轮不同运行实际取回，按资源记录 fresh 请求数、业务成功、绑定、完整度和投影差异；第一次页面捕获不能冒充该资源复采。
5. 交付**单项目所需数据对照表**，按[主文档的逐项栏目](../TAX-MONTHLY-DATA-CHAIN.md)列项目 / 表版本 / 字段或资料类别 / 本期发生或累计或结转或比较口径 / 历史窗口 / 已观察税局入口与契约证据 / 本机已有来源 / 获取状态 / 缺口归属 / 负责人及阻断。没有官方或实际表单依据的字段标待核，不按税种名称猜资料；M1 允许表单依赖未核项，但不能声称需求完整。

**建议文件**：`06-workbench/server/tax-live-collection*.mjs` 等 main 既有 live 模块；如选用 PR #35 的 query 模块，按该 PR 实际文件清单另行授权；对应 HTTP / Agent / MCP 入口与合成契约测试。避免另建平行税局框架。

**验收**：已报期样本不新建待办；同数不同期间 / 键不混；跨企业、跨期间、过期会话、schema 漂移、分页不全关闭消费；MCP 两轮真实发送与结果证据逐资源齐全。此包不宣称已下载表单或清单完整。

### M2 · 同项目详情、原件下载和资料账册

**输入**：M1 已确认项目 / 期间 / 申报版本与真实查询结果；实际官方表单 / 详情入口。先核固定只读列表 → 详情 / 表单 → 官网确有的只读下载。没有观察与业务证据时不猜详情接口。

**实施**：

1. 区分结构化查询、税局原始表单 / 附件 / 回执文件、本机派生导出；保存它们到具体表字段的关联。按该字段依赖追溯本期发生、期初 / 结转、本年累计、上期 / 比较期，记录 requested / covered 窗口与停止原因。
2. 对官网确有的文件下载实施[主契约](../TAX-MONTHLY-DATA-CHAIN.md)的作用域守卫、受控分页 / 字节上限、内容类型与实际类型、HTML 登录页 / 空文件 / 截断检测、原子保存、校验值、重复 / 版本冲突、短效链接更新与有界重试。
3. 文件和 manifest 只留本机受限忽略目录；MCP 仅返回 opaque ref、状态和计数。链接、nonce、运行参数及原文不进入模型 / Git；文件读缓存不计 fresh 请求。
4. 核文件 / 详情的企业、期间、表版本与列表申报版本一致，更正前后回执分别关联。两轮后端实际取回按资源比较，失败、未运行、动态差异逐项解释。
5. 若有效完整查询与来源证据证实官网不提供某资料 / 下载，记 `confirmed_unavailable` 与范围；未知支持、未实现、登录失败仍为技术缺口，不能自动索取企业资料。
6. 完善 M1 的单项目所需数据对照表：以实际表单字段 / 版本核需求，逐项补齐必要往期来源、请求 / 覆盖窗口、文件或结构化证据和缺口归属；仍待核项明确负责人。该对照表是资料链路交付物，不等全规则平台完成。

**建议文件**：选定已有 query / live 模块；聚焦新增私有文件存储与资料 manifest 模块、受控下载适配层及定向测试；`server.mjs` / `agent-tools.mjs` / MCP 仅做必要接线。具体新增名由派工约定，不用工具名代替实现。

**验收**：同名文件跨企业 / 期间不串；相同内容去重、变更保版本；过期链接、截断、类型伪装、分页重复 / 重试均可解释；本机稳定证据可读且完整。单项目所需数据对照表逐项能说明要什么、往期从何取、未取得由谁处理；待核需求不宣称完整。下载未实现时诚实记待办，不以本地 CSV / PDF 当税局原件。

### M3 · 桥接现有工具、拆分技术和企业清单

**输入**：M1 / M2 的单项目私有资料和来源契约，以及本机账套可信绑定；原值留在可信层。

**实施**：

1. 核 `TaxGateway` 5 类与 acquisition / preparation 10 类资源的支持交集。额外 current_obligations / declaration_history / accounting_filing / invoices / payments 在原通道 unsupported，默认生产 adapter 为空；逐项建立真实适配 / 注册或清楚 unsupported，不只再加工具名。
2. 建立独立 TaxLive / TaxQuery 证据 → 规范化私有 store → `TaxAcquisition.prepare` / `TaxPreparation` 的桥接与追溯。消除 `fields=[]`、metadata only、进程内 Map 被误当真实完整证据的路径；是否持久化、是否 fresh 和是否匹配分别报告。
3. 用企业 + 账套 + 项目 + 期间 + 表 / 模板 / 版本 + 来源凭据关联资料依赖，核真实身份匹配而不是预置 true；区分来源冲突、缺行 / 缺期间、资料已有但未接线。
4. 只有有效查询核实税局不提供 / 确实无记录，且本机既有资料不足、业务字段确需时才生成企业补充项。企业清单逐项列影响表字段、用途、期间、格式、已尝试来源、负责人 / 期限、阻断与补充状态；未实现 / 登录失败 / 覆盖不全只生成内部技术任务。

**建议文件**：`06-workbench/server/tax-gateway.mjs`、`tax-acquisition.mjs`、`tax-preparation.mjs`、实际 live / query 私有证据层，必要存储 / 绑定 / Agent / MCP 接线及对应测试。账套绑定和资料接线先约定契约，禁止让同文件多人各补一套。

**验收**：not_implemented / login_failed / partial 样例中企业补充清单为空且有技术待办；有效查询与本机核对后确缺必需资料才索取；source_conflict 待核不自动覆盖；累计不重算重叠区间，历史申报不覆盖本期账；真实资源没有桥接时准备状态仍阻断。

### M4 · 企业事实 → 每月项目 → 表单和资料要求

**输入**：已确认来源的企业事实（含有效起止）、税费认定 / 登记、有效官方规则或税局认定证据、必要企业事件及已核表单版本。可先对已确认的一个项目制作依赖，逐项扩大。

**实施**：建立工作月与事项所属期独立模型；分开义务候选 / 确认、已申报记录、资料依赖集合。适用性、生命周期、证据等级与取数完整度分开。表要求关联官方版本 / 有效期、字段到资料依赖、阻断条件和完整性证据。规则未核保留 unknown；保持 preparation 保守阻断，不为展示计划自动解除恒定 gaps。

**建议文件**：`tax-preparation.mjs`、`tax-acquisition.mjs`、已有 profile / 表格式模块及必要私有证据 schema；官方模板与规则逐项目另附安全证据索引。完整 PRD 范围不能擅自删减，但单项目交付不得冒充全量覆盖。

**验收**：同一工作月可有月 / 季 / 年不同所属期事项；上期已报、行业名称、无待办、企业所得税核定信息 0 条不足以判本期义务；已报期 verificationTarget 为 completed_period，旧 currentPending 标志不滥用；模板未知不得称可上传；完整性未证实不得宣称完整月计划。
