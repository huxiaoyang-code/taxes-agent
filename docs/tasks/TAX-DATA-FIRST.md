## 五步验收

| 步骤 | 必交结果与门槛 |
|---|---|
| 0 会话 / 身份 | 明确目标浏览器与页面、当前主体 / 可办理企业范围和唯一会话所有者；仅安全元信息进入模型 |
| 1 第一遍真实发现 | 页面实际请求 / 响应证实的接口 / 数据可得性清单；结构、类型、空值、日期、分页、业务错误、作用域和副作用齐全；不猜端点 |
| 2 第二遍真实采集 | 最小本机后端在同一有效会话再次实际拉取，日期有界 / 分页完整 / 重试限量；识别过期需人工登录；快照重放不能过关 |
| 3 本机真实处理 | 规范化 / 去重 / 来源关联与数量、期间、覆盖缺口核对；解释两遍时间 / 状态变化，不强求逐字节相同；缺账务先查本地账套 |
| 4 首条业务闭环 | 画像事实及有效期 → 应办事项 → 表单字段 / 来源 / 补项 → 预填校验 → 冻结版本确认 → 正式提交 / 回执；超时先查状态，避免重复 |

应办事项综合税费种认定、当期待办 / 已报、必要历史、官方有效规则、企业事件事实；不以菜单 / 待办 / 历史单独推全义务。财报报送、纳税申报、缴款独立；规则与表单按地区和期间生效版本核实。当前五步均未全部验收，不编工期。

## 数据与操作约束

- 候选为授权企业、画像 / 税费种、待办、申报历史明细 / 回执、财报、缴款欠税、发票、社保个税；不承诺均可取，税局未必有科目 / 期初 / 凭证。
- 真实响应与处理留本机受限、Git 忽略目录。非凭据业务响应可按用户要求保存；认证头 / Cookie / token / 票据 / OTP 不进业务产物、日志、模型或 Git。
- 模型 / subagent 仅得 schema、脱敏 / 合成样例、成功状态、计数、覆盖、失败类别；不回显企业身份或账簿原文，不用合成数据冒充真实处理。
- 真实接口以本轮实际证据为准；历史线索 / 当前观察 / 首次成功 / 二次采集验证 / 产品接线分级。SSO 签票、标已读、身份切换非无副作用读取，必要性与范围先反馈。
- 自动点击 / 点击脚本仍禁用；受控操作只接受正常查询参数，不透传任意 URL。正式开票 / 申报 / 缴款等外部写操作由操作者按明确冻结版本、批次确认。

## 最多三路并行

1. 一个会话所有者负责真实证据与限量采集。
2. 一个实施者等真实脱敏契约后做最小接口实现，不操作同一真实会话。
3. 一个实施者做官方规则 / 字段映射、合成数据处理与独立验证，真实结果只收安全摘要。

不多窗口同时切身份；共享接线与文档串行整合。不把接口尚未证实当作可猜测开发的授权。
