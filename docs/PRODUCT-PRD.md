## 1. 最终产品形态与用户旅程

**[已确认]** 最终形态：

- 本机**单用户**财税工作台：一名操作者在自己电脑上运行，可对**多家企业 / 多个账套**批量处理；**批量多账套 ≠ 多租户**。
- **不做** SaaS、多租户、租户权限平台、对外服务或账户体系；只保留本机需要的账套隔离、操作日志 / 审计留痕、备份恢复与凭据安全。
- 客户端以 **Codex / MCP + 可信最小 UI** 为主：模型侧只处理安全引用与状态摘要，**真实凭据 / OTP 只在本机可信回环界面录入**。
- 全国电子税务局是 **V1 必做目标**；当前**真实接入数为 0**，预留接口不等于已接入。

**[已确认]** 目标用户旅程（逐段）：

1. **本机身份与 OTP**：操作者在本机可信界面输入账号 / 密码 / 验证码 / 扫码 / 实名；模型与日志只收不含原文的状态摘要。
2. **企业 / 账套**：办税员身份 → 授权企业清单 → 选择或绑定本地账套；区分「身份 / 授权企业 / 税局登记申报数据 / 本地账套会计明细」四层，不混同。
3. **来源核实与导入**：每项外部数据先过来源与完整性门槛（来源、字段、期间、口径、完整度、授权、证据），再进标准 DTO、映射预检、定向导入。
4. **会计处理**：双准则账务、期初 / 凭证 / 计提摊销 / 结转 / 封账，含现金流与资产一致性。
5. **报表**：内部资产负债表 / 利润表 / 现金流量表（附余额表 / 明细账）与税局财务报表申报格式，**两类都要**。
6. **发票**：采集 / 去重 / 原件 / 入账关联，与开票预检 / 税码 / 蓝红票 / 状态回查。
7. **企业各税种申报与个税**：数据准备 / 计算 / 复核 / 正式发送 / 回执 / 状态核对 / 更正处理；个税独立登录授权链路。
8. **审计与恢复**：操作留痕、脱敏审计、备份完整性与可验证恢复、迁移可回退。

**[方案待定]** 首版是否需要独立桌面程序 / 安装包；批量任务的可视化界面层级。

## 4. 自动化边界（外部写操作）

> **[方案建议，待 review 冻结]** 本节及 §5~§8 中，除 §0 已确认的产品范围与角色外，**新增工程实现与建议验收**均为方案建议，待 review 冻结。

**[已确认]** 以下为不可逾越的边界，属所有 P0 需求的前提：

- **允许**：数据准备、校验、批次计划、生成待审阅文件、状态回查。
- **开票 / 红冲 / 正式申报**等**真实外部写操作**：须由用户在本机**预览并明确确认**，可按**可审阅批次**授权；验证码 / 实名**不绕过**。
- **请求超时**：先**回查**再重试；**提交成功但无回执保持「未知」**，不可重复发送。
- 用户要求「正式申报功能」**不等于本次授权真实报送**；本轮**只写文档**，不实际登录、开票、申报或缴款。
- 缴款是否纳入 V1、银行真实支付——**不自行假设**，见 §10。

## 5. 会计验收（独立金额样例，覆盖关键边界）

> **[方案建议，待 review 冻结]** 本节验收手段为建议；已确认的是「关键金额需独立验算」这一原则。

**[已确认]** 报表的关键总额与行次必须用**手工或独立构造的预期值**断言，`导出 = 页面` / 同源互比不作为证据。合成自动测试、接口结构验证、获授权用户本机真实验收**分别记录**。

必须覆盖的场景：

1. 复杂混合现金流（含比例分摊限制的显式记录）。
2. **真正独立**的间接法勾稽。
3. 两准则（小企业 / 企业会计准则）与父子科目。
4. 年中启用 / 跨年 / 连续两月。
5. 已过账范围（草稿、反过账不进金额）。
6. 资产卡片与总账一致性、连续期间计提完整性。
7. 重复导入 / 版本变更 / 次月导入。
8. 闭账拒写；错误原子性（失败不落库）。
9. 来源缺失阻止正式输出。
10. 企业切换 / 跨账套不串账。

## 6. 税务验收

> **[方案建议，待 review 冻结]** 三层验收分为建议分工，非用户逐项确认。

**[已确认]** 覆盖维度：**官方模板的地区 / 准则 / 频次 / 单位 / 精度 / 版本**、全字段、文件结构、上传兼容性。验收分三层记录：

1. **合成自动测试**：合法结构 + 独立金额样例 + 负路径。
2. **接口 / 结构验证**：字段、勾稽、版本标注。
3. **获授权用户本机真实验收**：真实数据只在用户本机，只回传不含业务 / 身份原文的摘要。

发票与企业 / 个税端到端需覆盖**回执、未知状态、重复请求、失效撤权**。真实数据不进模型 / GitHub。
