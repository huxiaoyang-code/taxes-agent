# 产品需求文档（PRD）· v0.2 业务需求已确认，研发方案待评审

> 本文只写产品目标、业务边界、功能范围和验收标准。业务范围已经用户确认；**具体技术方案、架构、工具与实现方式由研发自行评估并提交评审，本文不作规定**。
> 相关：[高级 review 任务单](tasks/PROJECT-REVIEW-SHOWMAKER101.md) · [本轮交接](handoffs/PROJECT-PRD-REVIEW.md)。
> 本版已确认范围优先于旧方案中较窄的阶段范围。

## 一、产品说明

1. 本产品是本机单用户财税工作台：一名操作者在自己的电脑上使用，可对多家企业、多个账套批量办理日常财税事项；不做 SaaS、多租户、账户权限平台或对外服务，只保留本机需要的账套隔离、操作可追溯、备份可恢复与敏感资料保护。
2. 全国范围属于首版目标。福建漳州是首个真实验收地区，先验收；**漳州通过不等于全国完成**，其他地区仍需分别验收。
3. 典型使用路径：办税员登录并管理授权企业 → 选择企业与账套 → 首次旧账导入、以后按连续月份接续做账 → 日常账务处理 → 出内部报表和税局要求的财务报表文件 → 发票采集与开票 → 企业各税种与个税申报 → 缴款、社保、非税办理 → 结果与凭据核对。
4. 凡是真实外部提交类动作（开票、红冲、正式申报、缴款），都要由操作者在前确认，并按明确批次一次确认一批；**自动点击浏览器、点击脚本这一路线已被用户明确永久否决**，不再作为任何阶段的做法或备用方案。

## 二、业务边界

**做**：本机单用户、多企业多账套批量办理；两套会计准则；全国首版目标；真实税务与发票等外部业务的正式办理；结果与凭据核对。**不做**：SaaS、多租户、租户权限平台、对外服务、账户体系。

**不擅自扩张**：完整业务覆盖清单交项目经理确认；边界细项不得自行增加，也不得删减已确认范围，**不得把已确认的主范围改写成"待定"或"范围外"**。

## 三、功能范围与完成标准

两套准则都必须支持：**小企业会计准则、企业会计准则**。

### 3.1 登录、企业与账套

| 能力 | 完成标准 |
|---|---|
| 登录与授权企业 | 可在本机完成登录与必要验证步骤，失败 / 超时 / 授权变化有明确提示、不静默通过；能读取该办税员名下的授权企业清单并与本地账套对应，不同企业资料不混用 |
| 企业 / 账套选择 | 可切换企业、账套分别办理；切换后不会串账；账号、验证码等原文不出现在日志或对外记录中 |

### 3.2 账务处理

| 能力 | 完成标准 |
|---|---|
| 首次旧账导入 | 首月按原始资料建账；资料不足时明确提示缺什么，不凭空补零 |
| 连续月份接续做账 | 后续月份在原账套上接续；连续两个月可出表，不重建、不覆盖已有数据 |
| 科目与期初 | 科目、期初余额按所选准则建立，可与原始资料逐项核对 |
| 凭证与过账 | 凭证录入、审核、过账；未过账内容不计入报表金额 |
| 计提、摊销、结转、结账 | 按期完成折旧摊销、损益结转与结账；已结账期间不再接受新的记账 |
| 辅助核算 | 支持项目、部门、往来等常用辅助核算维度，并能按维度查账 |
| 银行流水与银行对账 | 可处理银行流水并与银行账对账，差异项可查看、可核对 |

### 3.3 报表与输出

| 能力 | 完成标准 |
|---|---|
| 内部报表 | 资产负债表、利润表、现金流量表，另附科目余额表与明细账 |
| 税局要求的财务报表文件 | 能按税局要求生成可提交的报表文件；生成成功不等于已申报 |
| 输出格式 | **Excel 与 PDF 都必须支持**；现有 CSV 导出保留可用，但不限定只能用 CSV |
| 金额正确 | 报表关键金额可用独立构造的预期值逐项核对，不能只以"导出成功"作为验收 |

### 3.4 发票

| 能力 | 完成标准 |
|---|---|
| 采集与查看下载 | 可采集发票、查看与下载原件，重复发票能识别去重 |
| 开票与红冲 | 开票前有预检和操作者确认，不开出不合规的票；红冲可追溯，与原票关系可查 |
| 结果核对 | 每张开票、红冲都有结果与凭据可核对；结果不确定时先核实，不重复办理 |

### 3.5 企业各税种申报

| 能力 | 完成标准 |
|---|---|
| 覆盖范围 | 覆盖企业实际适用的各税种，含应办的月度、季度、年度事项及更正业务；**不得缩小成只支持少数几种税** |
| 计税与核对 | 各税种能计税并逐项核对，缺资料时明确阻断，不填零顶替 |
| 正式申报 | 申报前由操作者确认；能正式提交并取得受理结果 |
| 结果与回执核对 | 申报结果、回执、状态可核对；不确定时以核实为准，不重复申报 |
| 覆盖清单 | 研发按真实业务整理完整覆盖清单交项目经理逐项验收；需要细化的地区差异写成清单交项目经理确认；边界细项不得自行增加或删减已确认范围；未核对完整清单前不得声称已覆盖各税种 |

### 3.6 个人所得税

| 能力 | 完成标准 |
|---|---|
| 业务范围 | **工资薪金、劳务报酬、经营所得和年度汇算全部包含** |
| 资料与计税 | 能维护人员收入与扣除资料并计税，资料不足明确提示 |
| 申报与反馈 | 能正式申报并取得申报反馈；结果可核对，不重复申报 |

### 3.7 缴款、社保与非税

| 能力 | 完成标准 |
|---|---|
| 范围 | **正式缴款、社保、非税全部纳入首版**，不列为待确认或范围外 |
| 能办应办事项 | 能办理相应的应办申报与缴费事项，不只是展示范围或完成缴款 |
| 结果与凭据核对 | 每次办理都有结果与凭据可核对；申报状态与缴款状态分别核对，**申报成功不等于缴款成功** |

### 3.8 批量与多企业办理

| 能力 | 完成标准 |
|---|---|
| 一次批量发起 | 可一次性对多家企业发起办理 |
| 进度与逐企业结果 | 有整体进度，能逐家查看成功、失败和原因；某家失败不影响其他企业，可只对失败企业重办 |
| 两种二十家模式 | 一个办税员名下二十家、多个办税员合计二十家，两种模式分别验收 |
| 不混、不重复 | 资料不跨企业混用；同一事项不重复建账、记账、开票、申报或缴款 |
| 命令行批量入口 | 提供命令行批量操作入口，可批量发起、查看进度结果并继续未完成事项；**不规定命令形式或技术选择** |

### 3.9 资料、可追溯与恢复

| 能力 | 完成标准 |
|---|---|
| 敏感资料保护与可追溯 | 敏感资料仅按操作者授权用于相应业务，不向无关人员或服务披露；正常办理按授权提供必要资料，资料保护不妨碍已确认的正式申报与缴款；导入、更正、重办、恢复等关键动作有记录可查 |
| 备份与核实 | 变更有备份，恢复后可验证数据完整；任何结果不确定的办理先核实再决定，**不得重复办理** |

## 四、目标规模与速度基线

1. **同时办理家数**：二十家企业"实际同时处理"是硬目标，**不能只提交二十条排队**。
2. **速度基线**：用户提供的事实是"五名熟练会计合计每月约 200~300 家"。这是用户给出的业务统计，非本项目实测，也不作其他换算。
3. **建设目标**：以该区间**上沿**为基准建设。在可比工作月、可比企业业务复杂度、资料质量和办理范围下，**一名操作者配合产品每月正确完成的企业申报数大于 300 家**。
4. **统计口径**：完成数量按相同企业、相同申报期间和约定必办事项的完成情况统计，申报结果和回执可核实；同一企业的多个税种、多次重试只算一家。统计需去重，代表性业务组合由后期真实试点与项目经理确认；**不能只挑简单的零申报企业证明全面达标**。

## 五、验收分阶段

1. **二十家并发与月产出分别验收，二者不能互相替代。**
2. **前期验收（可先做）**：用演示或合成样本验证功能正确、二十家同时推进、失败可恢复、容量有依据，并提交评估结论。前期**不得提前声称真实月产出已达标**。
3. **后期验收（最终口径）**：在获得授权的企业实际使用中，分别验证一个办税员名下 20 家和多办税员合计 20 家的"实际同时处理"，并记录一个可比工作月的正确完成企业数、整段耗时、人工介入情况、失败补办情况和结果质量，**以真实记录验收大于 300 家**。前期演示或合成结果不能替代真实并发验收，也不能替代月度产出证据。两项仍分别验收。

## 六、未达标应对方案的交付要求

研发需提前提交"未达标应对方案"，用非技术表述，内容包括：

1. 哪些情况可能导致二十家并发或月度产出不足，以及各自影响；
2. 可以选择的改进或替代办法、临时保证业务连续办理的措施，以及各事项负责人和重新验证办法。

要求：临时人工处理**单独计时、单独计量**，不能拿人工补办冒充产品产出，也不能降低正确性、资料保护、正式办理确认和既定目标；方案如需调整由项目经理确认。**不得写点击脚本类备用方案。**

## 七、现状简述（供 review 对照，不作完成度评价）

- 已有：基础记账、旧账导入、内部表格导出等基础能力。
- 尚未交付：真实税务接入，以及完整的发票、申报、缴款、社保、非税办理；两套准则完整口径、二十家并发与每月产出目标也尚未验收。
- 准确差距清单由高级 review 负责给出，**本 PRD 不作完成百分比结论**。

## 八、研发需交付的事项（技术方案由研发自选）

1. 完整业务覆盖清单（税种、地区、票种、报表版本等）交项目经理逐项验收。
2. 分期实施与排期依据，以及二十家并发与月度产出的两阶段验证计划。
3. 未达标应对方案。
4. 必要的边界细化清单，交项目经理确认。

以上交付物与 [高级 review 任务单](tasks/PROJECT-REVIEW-SHOWMAKER101.md) 的要求一致；技术方案、架构与工具选型由研发自行评估提交，本 PRD 只确认范围、效果和目标。
