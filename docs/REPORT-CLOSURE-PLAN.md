## 1. 用户目标（覆盖旧优先级）

最终交付是**报表闭环**：

> 导入一个办税员账号 → 接收并输入验证码 → 登录 → 获取该办税员名下企业 / 账套 →
> 对所需账务数据完成财务操作 → 生成报表。

用户明确回答「两类都需要」：

1. **内部报表**：资产负债表、利润表、现金流量表，附**余额表 / 明细账**；
2. **税局财务报表申报格式**：按税局要求的报表模板与字段格式导出。

前端展示次要，功能优先。**两类报表都不得缩减为其中一类**；任一类的失败或降级都必须显式记录，不能以另一类代替。

本文件把该目标拆成**按依赖顺序、可独立 PR 验收的工作包**，并明确每一包当前真实起点、
数据可得性门槛、验收场景与失败路径。**本文件编写时（2026-10-15）不实现任何一包功能**；
后续 RC-B B0 / B1 已由同事 PR #15 实现并合并（见各包当前状态）。

- `06-workbench/server/tax-gateway.mjs`：**允许必要的适配器接线与凭据引用改造**（不改既有状态机语义）；可**选择性选用** `tax-browser.mjs` / `tax-browser-http.mjs` / `tax-import.mjs` 的模块，**不自建平行实现**；

**必须区分的四层（不得混同）**
1. **办税员身份**（当前登录人 / 角色，脱敏）；
2. **授权企业**（该身份被授权办理的企业清单）；
3. **当地税务登记 / 申报数据**（税局侧的登记与申报信息）；
4. **本地账套与会计明细**（本地 SQLite 中的科目 / 期初 / 凭证）。

**凭据与隐私硬约束（不可协商）**
- 用户的**账号 / 密码 / 验证码只能由用户在本机可信界面输入**；**绝不要求用户把账号 / 密码 / 验证码发到本聊天、模型任务、任务单或日志**。
- 权限边界按**通道**划定，不得笼统写作「只接收安全引用」：
  - **模型可见的 MCP / Agent 接口**：只接收**安全引用**（`credentialRef` 之类）与**不含真实业务与身份原文的状态摘要**（会话状态、计数 / 布尔标志、脱敏展示用标识），不接收明文凭据或验证码，也不接收可还原真实企业 / 个人的原文。
  - **本地可信 UI → 本地凭据服务 / 浏览器的专用回环通道**：**允许**传输**瞬时**账号 / 密码 / OTP，用于用户在本机录入并完成本机登录；该通道必须严格同源、绑定当前会话，**禁止记录或回传任何敏感值**（不写日志 / 不写 DB / 不进响应 / 不进模型）。
  - **不得把真实企业清单或「脱敏但可识别」的身份默认当作可发模型的非敏感状态**；**企业选择与真实报表在用户本机展示与处理**，模型侧最多看到不含原文的计数 / 状态。
  - 用户**不需要**把凭据发到聊天、模型任务或模型服务；本机软件自行完成真实数据处理；**禁止员工读取或转送真实数据**。
- 凭据与会话**留在本机**，不进模型 / 日志 / Git / 报表 / 响应；沿用 `tax-gateway.mjs` 的 DTO 白名单与脱敏。
- **默认以人工本机输入为准**；**保留**后续「经用户明确授权的接收渠道」接口（如本机短信 / 邮箱助手），但**不承诺自动读取任意短信 / 邮箱**。
- **真实数据人工验收只在用户本机完成**，只回传**不含业务 / 身份原文的结果摘要**；**禁止员工工具（含 `read`）读取真实数据**。

**输入 / 输出**
- 输入：本机可信界面录入的凭据引用 + 会话票据；企业列表（名称 + 税号，须严格校验）；用户本地确认的建账三要素。
- 输出：`办税员身份记录`、`企业 ↔ 账套 绑定记录`（含 region / city / source / imported_at）、`凭据引用记录`、可查询的会话状态。

**失败路径（必须覆盖）**：会话过期、验证码错误 / 超时、二次人机验证、授权撤销、企业切换与**串账**（跨账套 / 跨企业读取一律拒绝）；关闭采集会话**不代表**已从税局服务端退出。

**完成标准**：合成数据下可完整走到「登录 → 企业 → 账套」且异常路径全部有明确错误码；用户本机完成一次真实登录验收并记录（**脱敏摘要**）；RC-1 结束时**必须留下「目标账套」绑定**（供 RC-2 定向导入使用）。
**必要测试**：状态机 / 会话隔离 / 跨账套拒绝 / 迟到结果丢弃（复用 `tax-contract-test.mjs` 的模式）；绑定表唯一性与级联删除；**凭据与验证码不出现在任何 API / MCP 响应与日志**的断言。**自动测试只用合成数据**。

### RC-2 · 目标账套定向导入、数据落地与重试（幂等），含最小恢复能力

**目标**：任何外部来源（税局导出、用户本地资料、草稿采集）进入本地账套时，**批次可追溯、重复导入不重复建账 / 过账、失败不部分落库、可安全重试**；并**把解析出的财务数据定向写入 RC-1 已绑定的目标账套**。这是旧的 `IMPORT-IDEMPOTENCY` 在新优先级下的归位，不再是第一优先。

> 本包**必须拆成两个可独立 PR 验收的子步骤**：**RC-2a 首次建账 / 填空账套**与 **RC-2b 已绑定账套后续开放期间追加**。原先把**所有**导入都限制为「空账套」会让已绑定账套的后续月份无法持续闭环，因此**空账套限制只作用于 RC-2a 的首次建账 / 填空账套模式**。

#### RC-2a · 首次建账 / 填空账套（空账套限制只作用此模式）

**目标**：为新绑定企业建立可出表的账套基线——新建并绑定账套，或把首次数据填入已绑定的**空账套**（仅企业档案 + 标准科目表）。

- **空账套限制仅适用本模式**：写入前校验目标账套确为空（无凭证 / 期初 / 资产），否则拒绝。
- **首次去重先于空账套拒绝**：查询「稳定业务键 + 内容版本」的已有批次必须**先于**空账套校验；命中则**直接返回已有结果**，不得因第二次提交时账套已非空而**误拒绝**。
- **禁止覆盖既有凭证、期初、资产**；**禁止写入已封账期间**；**同一企业 / 账套绑定及同一导入业务范围的重试或后续期间不得重复建账**。**这不是「一家企业只能有一个账套」的产品限制**；账套标识 / 年度 / 准则边界由管理者派工时在任务单里明确。

#### RC-2b · 已绑定账套后续开放期间追加（持续闭环）

**目标**：同一企业账套在**后续期间**继续追加数据，使多个月份可持续闭环，而不重建 / 不覆盖既有账。

- **只追加新业务事实**：使用**稳定来源业务键 + 内容版本**判定；**只追加新业务事实 / 新期间数据**，**不覆盖既有凭证、期初、资产**；重复提交**返回已有结果**（不重复建账 / 不重复过账）。
- **同键更正必须显式**：同一业务键内容变化时，必须走**明确冲销 / 更正流程**（留审计），**不得静默覆盖**；更正后旧业务事实的追溯链保留。
- **拒绝写封账期间**：目标期间已封账则明确拒绝，不得强行追加。
- **同一绑定范围不得重复建账**：同一企业 / 账套绑定及同一导入业务范围的重试或后续期间只能追加到既有账套，**不得**重复建账；**不得据此新增「一家企业只能一个账套」的产品限制**，账套标识 / 年度 / 准则边界由派工任务单明确。
- **现有草稿的绑定唯一性只是草稿事实**：草稿中的企业 ↔ 账套绑定唯一性属其当前实现，**不能自动扩展为产品规则**；具体边界由管理者派工时写明。
- **数据不足 / 不明来源拒绝出正式表**：来源不明或完整度不足时，标记「数据不足」并**拒绝把该账套标记为可出表**，不得以部分数据产出正式报表。

**必须解决的缺口：定向导入**
- **现状**：`importAccountSet`（§2.1）**总是新建账套**；草稿的 `importFromTaxBrowser(mode="create")` 同样走 `createAccountSet`，且**建出的是空账套**（仅企业档案 + 标准科目表），**不含科目明细 / 期初 / 凭证 / 余额**。
- **缺口**：RC-1 只完成「企业 ↔ 账套绑定」；RC-2 必须提供**「RC-1 绑定账套 → 定向导入财务数据」**的路径。
- **策略由任务契约选定**（二选一，不自行假设）：**(a) 新建并绑定**（导入时新建账套并写入绑定，属 RC-2a）；或 **(b) 填充已绑定空账套**（校验该账套确为空后，把数据写入既有 `accountSetId`，属 RC-2a；后续期间追加归 RC-2b）。
  **RC-2a 的两种策略都必须：只允许写入空账套**（否则拒绝）；**禁止覆盖既有凭证、期初、资产**；**禁止写入已封账期间**。**RC-2b 不受空账套限制**，但同样**禁止覆盖**与**禁止写封账期间**（见上）。

**允许改动**：`06-workbench/server/db.mjs`（批次表、稳定业务键、审计事件表、步骤状态表）、`accounting.mjs` 的**导入入口**（新增定向导入，不改报表算法）、`agent-tools.mjs`、`server.mjs`、`test/*.test.mjs`、`06-workbench/README.md` 与 `05-reconstruction/codex/skills/legacy-book-import/**`（仅当导入契约变化时同步）；**`docs/INDEX.md` / `CHANGELOG.md` 与交接由管理者派工本地员工同步**，历史验收文档（如 `PHASE1-ACCEPTANCE.md`）**保留原文不改**；本方案列出的未来文件范围均为**派工前建议**，不越权由管理者亲写业务 / 交付文档（见 §7）。

**必须包含的转换与预检（不只是批次表）**
- **来源采集 / 文件解析 → 标准财务数据 DTO 转换**：把来源（税局导出文件、用户本地 CSV / JSON、草稿采集结果）解析并归一化为统一 DTO（账套 / 科目 / 期初 / 凭证），复用既有 `parseImportTexts` / `normalizeImportPayload` 的严格约束。
- **完整性与科目映射预检**：科目是否存在 / 是否需新建、方向 / 类别是否可映射、期初是否平衡；**数据不足必须显式标记**（见下）。
- **来源 / 期间 / 币种 / 准则 / 时间 / 证据摘要**：每条批次记录来源标识、期间范围、币种、会计准则、导入时间、**来源证据摘要**（文件摘要 / 页面来源，不含凭据与业务原文）。
- **数据不足标记**：来源缺失期间、缺失科目、缺失金额区间时，**标记为「数据不足」并阻止把该账套标记为可出表**；**未知源数据不等同 0**；与「合法导入格式中的借贷空栏允许 0」明确区分（见 §2.1）。

**幂等与冲突**
- **重复导入**：同批次重复提交**不重复建账 / 不重复过账**；**首次去重查询先于空账套拒绝，命中后返回已有结果**（不误拒绝）。
- **稳定业务键 + 内容版本**：使用**稳定来源业务键**（如「税号 + 期间 + 来源 + 凭证业务号」）**加内容版本**判定重复与变更，**不能只用内容 hash**（内容 hash 无法识别「同一凭证的合法更正」与「不同来源的同号凭证」）。
- **变更冲突 / 明确更正**：同业务键内容版本变化时，**默认拒绝并要求显式冲销 / 更正操作**（更正需留审计）；不得静默覆盖。
- **禁止覆盖既有凭证和封账**：RC-2a 写入前校验目标账套为空、目标期间未封账；RC-2b 只追加新期间 / 新业务事实，同样禁止覆盖与写封账期间。

**事务与跨企业结果（避免自相矛盾）**
- **单账套原子事务**：单个账套的导入在**一个事务 / 保存点**内完成，失败**整个该账套回滚**。
- **跨企业逐项结果**：批量导入返回**逐企业结果**（成功 / 失败 / 跳过及原因）。
- **明确两种语义并分别实现**：
  - **「失败整批回滚」**：适用于**同一次原子提交**内的失败（单账套事务）；
  - **「只重试失败企业」**：适用于**多企业批次**——已成功企业不重复处理，只重试失败项。
  两者不是同一层次，契约必须写清各自适用边界，不得混用。

**最小恢复能力（本包与 RC-3 共担，可按 PR 拆分）**
- **同账套串行防并发重复**：同一账套的导入 / 计提 / 结转**串行化**，防止并发产生重复过账。
- **持久步骤状态 / 崩溃恢复**：批次与关键步骤状态持久化；进程崩溃后可按状态**断点恢复**，**不重复计提 / 结转 / 过账**。
- **审计事件**：导入、更正、重试、恢复均留审计事件（谁 / 何时 / 对哪个账套 / 结果）。
- **变更前一致性备份与可验证恢复**：在破坏性操作前建立**一致性备份**——**SQLite 一致快照**（如备份 API / `VACUUM INTO` 等一致方式），**不直接热复制 DB 文件**；并提供**可验证的恢复**（能确认恢复出的数据一致）。
- 这些能力**按 PR 拆分**，但**不落入无限通用队列 / 通用批量平台**（见 §6）。

**输入 / 输出**
- 输入：来源标识 + 批次标识 + 稳定业务键 + 目标账套（RC-1 绑定）。
- 输出：`import_batches` 记录（状态：pending / success / failed / skipped / insufficient_data）、逐企业结果、审计事件、来源证据摘要。

**完成标准**：
- **RC-2a**：同一批次重复提交**不重复建账 / 不重复过账**；首次去重命中后重试**返回已有结果**（不因账套已非空误拒绝）；单账套失败整批回滚；多企业批次只重试失败项且不重复已成功企业；数据不足被显式标记且阻止标记可出表；状态可查询、崩溃后可恢复。
- **RC-2b**：**跨两个月连续出表**（首月建账 / 填账 → 次月追加 → 两月均可出表）；重复重试**不重复追加**；失败恢复**不串账**（不写到其他账套 / 企业）；同键更正走显式冲销 / 更正流程；封账期间与同一绑定范围内的重复建账被明确拒绝。
**必要测试**：重复批次、部分失败重试、**内容变化后重导（稳定业务键 + 内容版本判定）**、跨账套隔离、**断点恢复不重复计提 / 结转 / 过账**、**跨企业不串账**、备份快照一致性、原有导入严格校验回归不退化；**另加：跨两个月连续出表、重复重试不重复、失败恢复不串账**。

### RC-3 · 财务流水线完整性（科目映射 / 期初 / 凭证 / 计提 / 结转 / 结账）

**目标**：把「所需账务数据」变成可结账出表的账，并**核实报告算法 / 口径缺口**（不因函数已存在就宣称合规）。

**允许改动**：`accounting.mjs`、`coa.mjs`（如新增准则科目）、`server.mjs`、`agent-tools.mjs`、`test/*.test.mjs`；本包同时承担 RC-2 指派的最小恢复能力中与财务步骤相关的部分（同账套串行、步骤状态、审计、备份恢复）。

**必须核实的口径缺口（已识别，须逐项确认）**
- 会计准则字段可填「企业会计准则」，但建账仍载入同一份 `coa.mjs` → **两套准则未真正区分**；
- `cashFlowStatement` 按对方科目与金额比例分类，复杂混合分录 / 明细科目需验证；间接法末行直接取直接法经营净额，**不是独立勾稽**；
- `incomeStatement` 归集依赖名称 / 编码前缀 + 兜底「其他收入 / 其他费用」→ 与官方利润表行次是否一致未核对；
- `balanceSheet` 行项（如「其他应收款」「长期借款」的编码归并）为本地口径，**未对照官方模板**；
- 创建资产卡片**不自动生成购入凭证**，卡片与总账需一致性校验。

**完成标准（不得以“记为限制”代替验收）**
- 一条合成路径走完「科目 → 期初 → 凭证 → 计提 / 摊销 → 校验 → 结转 → 结账」，期末平衡、报表数字与凭证可追溯；
- 上述每个口径缺口必须**有明确结论**：**已修**，或——**若该缺口影响目标准则 / 数据 / 报表**——必须**补齐**，否则**显式阻止产出可申报文件**（见 RC-5）。**「缺口记为限制」不能代表适用目标的闭环验收通过。**

**范围弹性（不得一律排除）**
- 若发票、银行流水、工资、辅助维度中的任一项是**目标账套产出正确报表所必需的数据**，**不得一律排除而仍宣称闭环完成**；**先确保来源与必要映射入账**，独立完整的业务子系统排在后面（见 §6）。
- **未知源数据不等同 0**；严格保留现有「借贷空栏允许 0」的合法导入格式，与「整份数据不存在 / 缺期间 / 来源未知」明确区分（见 §2.1）。

**必要测试**：平衡与勾稽、封账保护、失败原子性、口径回归；**断点恢复不重复计提 / 结转 / 过账**、**跨企业不串账**、变更前一致性备份后可验证恢复。
**明确当前闭环范围（最小必需集）**：「所有财务操作」在本阶段**至少**指完成报表所必需的科目映射 / 期初 / 凭证 / 计提 / 摊销 / 校验 / 结转 / 结账；
其余（银行对账、完整的发票 / 工资子系统等）先按上面的「范围弹性」判断是否为出表必需，再决定并入或后排，归属见 §6。

### RC-4 · 内部报表导出（3 表 + 余额表 / 明细账）

> **当前状态（2026-10-16）**：**B1 五类内部 CSV 与 HTTP / 页面预览已随 PR #15 交付**（[REPORT-EXPORT](REPORT-EXPORT.md)）；本包**完整验收仍待** RC-3 接线与连续期间验收。以下是原完整完成标准，仍作为后续验收依据。

**目标**：报表**可下载**，不只是网页查看；导出结果**独立可核验**。

**允许改动**：`server.mjs`（新增导出路由，如 `/api/account-sets/:id/reports/:kind/export?period=&format=`）、新模块 `report-export.mjs`、`public/app.js`（下载按钮）、`test/*.test.mjs`；不改报表算法本身。

**验收必须基于独立预期金额 / 会计口径（不只与 API / 页面同源互比）**
- 除了「导出值与 API / 页面逐值一致」，还必须有**独立预期金额 / 会计口径**：用手工核算或独立构造的预期值断言报表总额与关键行次，**不接受「导出 = 页面」作为唯一证据**（同源互比无法发现双方同错）。
- **余额表不能只导出总试算合计**：必须包含**各科目**余额（含明细科目），并可与明细账下钻核对。
- 覆盖**期初 / 本期发生 / 年累计 / 期末**四个口径；明细账可按科目 + 期间追溯。
- 验收样例须覆盖：**跨期 / 年末**、**已过账范围**（草稿 / 未过账不得混入）、**混合分录的现金流量分类**等。

**交付格式（决策项）**
- **内部格式首步用 CSV** 可接受；
- **Excel / PDF 列为交付决策项**：在现有**零第三方依赖**约束下，PDF / Excel 生成需评估；如用户目标优先于该约束，**由管理者评估并决定是否调整依赖**（本方案不擅自引入依赖，也不擅自排除）。

**输入 / 输出**：输入账套 + 期间 + 报表类型 + 格式；输出下载文件（首步 CSV）。
**完成标准**：资产负债表、利润表、现金流量表、余额表（含各科目）、明细账（按科目 + 期间）均可下载；**独立预期值**通过；平衡与勾稽标志随文件输出。
**必要测试**：独立预期金额断言、导出内容与 API 逐值比对、中文编码、空账套、未登记期间、闭账期间、跨期 / 年末样例。
**失败路径**：期间缺失 / 非法、账套不存在、格式不支持 → 结构化错误，不产出半成品文件。

### RC-5 · 税局财务报表申报格式（导出，不等于报送）

> **当前状态（2026-10-16）**：**B2 未完成**。已交付税表法定结构参考 / 勾稽校验与就绪性阻断（[TAX-REPORT-FORMAT](TAX-REPORT-FORMAT.md)），但缺适用地区 / 准则 / 模板版本 / 上传格式，实际导出返回 422 `tax_template_unverified`；生成可上传申报文件的**成功路径**仍未完成。拒绝输出不构成 B2 交付。

**目标**：按税局要求的报表模板导出**可申报文件**，并明确合规边界。

**允许改动**：新模块 `tax-report-format.mjs`（模板与字段映射）、`server.mjs`、`test/*.test.mjs`、`docs/TAX-REPORT-FORMAT.md`。

**官方模板核实（自 RC-0 起可并行）**
- **官方模板、口径与合法格式的核实自 RC-0 起并行推进**，避免到 RC-5 才发现口径与模板不符而返工。
- 必须核实（不得先行承诺）：适用地区、适用会计准则、期间与币种、**官方模板版本**、字段映射与勾稽关系、**导出合法格式与校验规则**。
- **税局格式必须以真实官方支持格式为准**；**不默认通用 CSV 可申报**——若官方只接受特定模板 / 报文格式，必须按其要求实现。
- **正式模板与要求仍待官方核实**；未核实的法规结论不得写入。

**完成标准**：在**已核实适用地区 + 准则 + 完整数据**下，**两类文件都必须成功导出**（内部 3 表 + 余额表 / 明细账；税局模板格式），内部报表数据按官方模板字段导出，字段映射与勾稽通过校验；导出文件标注模板版本与生成时间。**无效或不支持的情形必须明确拒绝并给出结构化错误**（如缺字段 / 超长 / 非法值 / 未核实地区或准则 / 模板版本不符）；**若目标场景被拒绝，本包视为未完成**，不得把「阻止产出」当作交付完成。文档明确「生成可申报文件 ≠ 已向税局提交，实际报送 / 签章 / 缴款另行明确」。
**必要测试**：字段映射、勾稽、缺字段 / 超长 / 非法值拒绝、模板版本变更的显式失败、官方格式合法性校验。
**阻塞点**：官方模板与要求未核实前，本包**不得自称「符合申报要求」**；只能做到内部 3 表的结构化导出，并明确标注非申报格式。

### RC-6 · 端到端联调与交付

**目标**：把 RC-0 → RC-5 串成用户可验收的场景，而不是「UI 页面数」。

**功能验收场景（示例，用户可实际执行）**
1. 用合成数据：建账 → 定向导入（**RC-2a 首次填账**）→ 凭证 → 计提 → 结转 → 结账 → 出表 → 下载两类报表；**再在下一期间按 RC-2b 只追加新业务事实并重复提交一次，验证两个月连续出表、重复重试不重复、不串账**；
2. 用用户本机真实资料（经脱敏 / 用户自持）：完成一次「登录 → 企业 → 账套 → 财务操作 → 报表」；真实数据人工验收在用户本机完成，只回传**不含业务 / 身份原文的结果摘要**；
3. 异常：会话过期、验证码错误、授权撤销、重复批次、**重复提交同一批次**、**同键内容变更需显式冲销 / 更正**、封账后修改、崩溃后恢复、**跨企业 / 跨账套不串账** → 全部有明确失败与恢复。

**完成标准**：用户按场景逐条验收通过；README / 交接记录真实限制；**两类报表**均可下载；**跨两个月连续出表**（RC-2a 建账 / 填账 + RC-2b 后续追加）成立，重复重试不重复；**本方案不在此前任何一步宣称闭环达成，只有本包验收通过后才可声明**。
**必要测试**：全套 `npm test`（关键合并基线）、`npm run test:smoke`；**真实联调只用用户本机数据，不做自动测试**。

对每一项候选数据，执行前逐条填空；**无证据的行写「未知」，不得填「可用」，不得把缺失当 0 或凭空生成凭证**。

- 税局仅提供「申报汇总」时，可用于**核对**，不能代替明细账；核对差异须如实呈现。

## 6. 明确不做 / 范围弹性（本轮与近期范围外）

**不做**

- 不实现任何一包功能；**本轮只写方案与交接**。
- **不搭建泛用批量平台、任务大屏、展示优先的前端**；泛用批量队列 / 管理**后排**（报表出表是当前目标）。
- 不做多租户 / SaaS / 租户权限平台 / 对外服务 / 账户体系（本机单用户）。
- 不把税局申报表生成冒充为已向税局提交；不实现签章与缴款（另行明确）。
- 不为通过测试删改旧断言或伪造成功。
- 不要求用户把账号 / 密码 / 验证码发到本聊天、模型任务、任务单或日志。

**范围弹性（不一律排除）**

- 发票 / 银行流水 / 工资 / 辅助维度：**若目标账套出正确报表必需，则不得一律排除而仍宣称闭环完成**；**先确保来源与必要映射入账**，独立完整的业务子系统后排。
- **未知源数据不等同 0**；严格区分「借贷空栏允许 0」的合法导入格式与「整份数据不存在 / 缺期间 / 来源未知」（见 §2.1）。
- 个税、全税种申报计算等独立子系统：在 TAX-INTEGRATION / ROADMAP 中另有归属，本方案不并入，也不据此宣称闭环。
- **恢复能力**只做闭环必需的最小集（同账套串行、步骤状态、审计、一致性备份与可验证恢复），**不落入无限通用队列**。
