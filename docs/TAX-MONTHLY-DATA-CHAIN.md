## 1. 先交付什么

先选择**当前已申报期一个已确认项目**，串通该企业 / 账套的项目列表、历史申报明细或表单、经核实的只读下载、本机证据保存、项目 MCP → 后端两轮实际取回与资料差异；再扩展其他项目。单项目验收只说明该项目、该期间和该版本的链路成立。

企业适用性和必要表单证据不足时标记待核；可以继续核实已确认项目的历史取数，不能用猜测生成本期义务。全国规则平台、全部旧探索恢复、全企业档案齐备均不是首条单项目取数的当然前置；该项目自身必要的企业绑定、适用性、期间和来源安全仍必须满足。

| 用户要看到的结果 | 当前已具备 | 尚缺 / 先做 |
|---|---|---|
| 企业是谁、关联哪个账套 | 门户基础企业字段有局部真实证据 | 完整税费认定、有效期及可信账套绑定待核，不能以税号字段存在代替匹配 |
| 每个工作月应办什么 | 已有事项 / 资料的通用分类、缺项与阻断骨架；门户已申报记录局部复采 | 可靠义务来源、月 / 季 / 年任务归属和完整性判定待做 |
| 每项要哪些表和资料 | 已有准备工具和内部报表能力 | 项目 → 现行适用表单 / 版本 → 字段依赖清单和真实证据接线待做 |

## 2. 业务对象和期间

以下是**目标语义契约，非现有 API 支持声明**。真实日期、企业值及文件内容只在本机受限存储；模型侧使用随机不透明引用与核验摘要。

| 对象 | 必须表达的含义 |
|---|---|
| 企业与账套 | 企业绑定引用、账套引用、有效身份 / 授权来源及有效期、匹配状态；多账套按实际绑定，禁止跨企业混用 |
| 工作月 `workingMonthRef` | 操作者安排工作和汇总进度的月份，不能替代税款所属期 |
| 事项期间 `obligationPeriodRef` | 每项所属期起止、频次证据、办理期限、有效期；工作月内可含月度、季度、年度事项，不能按系统月份猜测 |
| 验证目标 `verificationTarget` | 本轮为 `completed_period`：已报期取数与资料复核；后续未报期另行验证，不能塞进 `currentPendingPeriodVerified` |
| 义务集合 | 候选项目与已确认适用项目分开；来源、官方规则 / 税局认定依据、适用时间、已知排除理由、未知覆盖项分别保存 |
| 已申报记录集合 | 实际申报项目、所属期、申报状态、回执与必要缴款关联；记录存在不自动证明当期完整义务集合 |
| 资料依赖集合 | 每项表单 / 模板 / 版本所需字段、来源、用途、期间和缺项；同一资料可服务多表，但须逐项链接 |

每个项目分别保留**证据等级、适用性、生命周期、取数完整度**。例如「历史已申报」「本工作月是否适用待核」「附件未接入」可以同时成立，不能压成一个成功 / 缺失布尔值。申报状态和缴款状态分别核实；取数通过不表示可正式提交。

企业事实需有效起止及来源证据；表单要求需官方模板版本、有效期及适用依据；取数结果需绑定、覆盖与失败状态；补充请求需补充中 / 已收 / 待核 / 已满足状态。上述对象均为拟议内部 schema，不是官方字段或已实现 API。来源冲突记 `source_conflict` 待核，不能自动选税局值或较新值。

义务来源优先核税局有效认定 / 登记与有效官方规则、实际事项 / 官方表单提示，并对企业事件的影响另留证据。历史项目只能提供候选线索，不能照抄为本期应报清单；企业所得税核定信息零条、待办空列表或某页面无数据均不能独立推出无申报义务。不确定项为「待核」，不写「不适用」。本文件不作具体企业税法判断，不臆造月 / 季 / 年规则。

## 3. 从项目到表单、资料和来源

每个已确认项目先列适用表单及版本，再从表字段反推资料依赖。资料关联键至少包括：**企业 + 账套 + 税种 / 项目 + 所属期 + 表单 / 模板 / 版本 + 来源凭据**；本机留来源事实，模型只见引用和覆盖结果。不同页面项目名相似，不能据此自动合并。

| 资料用途 | 核实内容 | 禁止替代 |
|---|---|---|
| 本期流量 | 本期交易 / 发票 / 收入支出及其表字段依赖；来源范围、截止点、完整度 | 不以历史累计直接当本期发生额 |
| 期初、累计、结转 | 依赖的期初余额、年初至今累计、上期结转 / 留抵等；起点及连续性 | 不把未知期初当 0，不重复累计 |
| 往期已申报表与回执 | 必要往期已报版本、更正关系、回执和用途（复核、累计起点等） | 已报汇总行不能替代表内明细或成功回执 |
| 附件及原始凭证 | 具体表字段所需附件、证明、原始凭证，期间与版本对应 | 税局附件不当然等于完整账务凭证 |
| 本地既有账务资料 | 经授权关联的账套数据、已有文件、账务口径与来源 | 账套已绑定不表示已导入完整会计明细 |

本年累计、上期 / 比较期与本期发生分别保存；逐字段记录 requested / covered 期间窗口及历史追溯停止原因。历史申报值仅按已核用途使用，不能覆盖本期账务；缺期间的累计不得判连续。

顺序：**税局已提供的本期及必要历史数据 / 文件 → 已授权本机资料核对 → 经证据确认仍缺且确需企业提供的部分**。每项记录已尝试来源及结果；不要因后端未实现而要求企业重复提交税局已有文件。必要历史范围由表字段依赖决定，禁止无界采集全部年份。

### 单项目所需数据对照表（首条链路必交）

M1 建立该项目对照表，M2 随详情 / 表单核实与实际取回逐项填充。**每行是一项具体字段或资料需求**，可以回答要哪些数据、从哪里取往期支撑、缺哪项交谁处理。真实表留本机，Git 只存结构和安全验收摘要；本轮不编造企业实例。

| 栏目 | 填写要求 |
|---|---|
| 项目及企业 / 账套归属 | 已确认项目引用与绑定，不能按同名项目混用 |
| 表单 / 模板版本及依据 | 官方或实际表单依据及有效期；尚无依据标待核 |
| 字段或资料类别 | 明确表字段 / 附件 / 回执等，不按税种名称猜需求 |
| 口径与用途 | 本期发生、本年累计、期初 / 结转、上期 / 比较分别记录 |
| 所需历史窗口 | 具体依赖窗口、追溯起止与停止原因；覆盖窗口另存 |
| 税局来源 | 已观察入口与已核契约证据状态；未知入口不猜 |
| 本机已有来源 | 现有账套 / 文件与证据状态，不重复索取已有资料 |
| 获取状态 | 已取 / 部分 / 未实现 / 登录失败 / 已验证无记录等，含范围与完整度 |
| 缺口归属 | 内部技术、业务待核 / 来源冲突、或经证实确需企业补充 |
| 负责人和阻断 | 下一步、负责方、期限及受影响表字段 / 计算 / 校验 |

### 缺口必须拆成两张清单

| 状态 / 原因 | 去向 | 企业是否补交 |
|---|---|---|
| 未实现、未接入、未验证、未观察、登录失效、权限未核、分页未完、schema 不匹配、请求失败 | 内部技术待办，注明负责人、重试 / 验证条件和影响字段 | **不能因此要求补交**，也不能记不适用 |
| 有效授权和明确范围下的完整成功查询，已证实无记录 | 记录查询范围 / 终点与业务含义，再核该字段是否仍需其他证据 | 仅业务确需且其他既有来源无可用资料时列补项 |
| 有有效证据表明税局确实不提供该类资料，或完整核对后资料确实缺失 | 核本机既有资料，仍不足则进企业补充清单 | 可以，须对应具体表字段和必要性 |
| 有适用时间与官方 / 税局依据证明该字段 / 项目不适用 | 业务结论并保留证据 | 不补交；不以取数失败推出此状态 |

企业补充清单每项至少列：企业 / 账套引用、项目 / 表单版本 / 字段、所需期间、资料用途、缺失原因、已尝试来源及证据状态、所需格式 / 最小内容、提供负责人、期限、阻断程度（阻断计算 / 阻断校验 / 可后补）和替代资料的核验条件。当前证据尚不能生成一份真实企业完整补充清单；本轮只能制定结构与生成条件，不能编造企业缺什么。

技术待办每项另列失败阶段、固定错误分类、受影响资源 / 字段、已尝试动作、责任人、恢复条件与待验事项。登录失败不等于税局无资料；覆盖不全不等于已验证空集合。

## 4. 取数和只读下载目标契约

继续适用[采集安全契约](TAX-COLLECTION-CONTRACT.md)中的身份、企业、完整文档、context / loader 与运行代次守卫。以下下载内容全部为**待实施 / 待实机验收**。

来源类型分别标记：网站结构化查询、税局提供的原始表单 / 附件 / 回执文件、本机派生导出。后者生成 PDF / CSV 不能冒充税局原件。官网是否确有只读下载必须实证；有效范围内核实确不提供后可记 `confirmed_unavailable`，不能造接口或原件，也不能由未知状态推此结论。

1. **来源先核**：只接受官方页面实际观察并核实业务语义、企业、期间、表单版本及无写副作用的固定只读来源。菜单、静态函数、HTTP 200、泛用 metadata 工具不能充当真实 adapter；不猜隐藏接口。下载所需附加请求也须先实际观察并核只读语义，不因“票据”等名称判写，也不泛授权未知鉴权请求；正式申报、缴款、更正、作废、备案变更及副作用不明动作禁止。
2. **作用域绑定**：下载前后核企业 / 账套 / 项目 / 所属期 / 表版本；旧页面、切换企业、过期登录及 context 变化均停止，迟到结果隔离。历史申报的更正版本和原版本分别保存，不能以相同文件名覆盖。
3. **范围有界**：本机可信层按已核来源约束分页 / 游标与范围，记录总数、页数、终点、重复和冲突；页数 / 字节上限、超时和重试次数显式有界。截断、未知总量或未到终点记 partial，不能宣布完整。
4. **文件校验**：检查状态及业务成功语义、内容类型 / 实际文件类型、字节数 / 长度、空文件、HTML 登录页伪装、截断和解码失败；必要时验证容器 / PDF 可读性。异常不作为成功文件消费。
5. **稳定本机证据**：受限忽略目录原子保存稳定文件及本机 manifest（来源、范围、获取时间、实际字节、完整性校验值、版本、关联资料用途和两轮运行记录），保存成功后才返回可消费状态；不将签名 URL 当长期证据，不把文件原文、签名链接或其查询值发模型 / Git。
6. **重复、过期与重试**：同业务键及相同内容去重；不同内容保留版本与差异，不能静默覆盖。短效链接失效须在相同已核作用域重新取得；禁止拿旧 nonce / 链接重放。失败重试不复制业务动作，不把缓存 / 本地文件读取计为 fresh 后端请求。
7. **真实链路验证**：首次页面观察建立契约，再由现有 MCP → HTTP → Agent → 后端形成两轮不同运行的实际取回；逐资源记录发送数、成功、来源 / 企业 / 期间 / 表版本、分页、字段与文件完整度。source / run、run / run 比较区分 matched / changed / missing / not_run / failed，并解释动态差异。
8. **安全输出**：MCP / 模型仅收到不由原值派生的 opaque ref、固定资源 / 错误代码、计数和核验布尔值；refs 本身不进 Git / PR。真实数据、文件内容、身份信息、凭据、URL / query、运行参数及 nonce 只在本机可信层处理，不读入实施 / 审查模型。

单资源取回成功、完整资料集合、表单可计算、可申报和已提交是不同结论。新链路的成功标志须覆盖本次 `completed_period` 的必要资源，保留旧 `currentPendingPeriodVerified` / `periodVerified` 原语义；本轮不得为已报期取数把它们改成 true。
