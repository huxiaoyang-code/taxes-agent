# 本机财税工作台：团队实施计划

需求确认：2026-10-13。用户授权由 Codex 管理本地 pi 与 Claude Code 并发开发，用 Git 分支、PR、测试和代码审查交付；审查验收通过后由 Codex 自动合并。

## 已确认范围

第一期完成六项已复现账务缺陷修复、已有功能的 MCP 接入、记账和导入规则，以及完整闭环验收。必须预留全国电子税务局办税员登录和信息获取接口，实际登录与取数可以在后续阶段落地。全国支持是产品目标，不能把空适配器标成已支持。

银行流水、发票、工资、辅助核算、正式开票和申报留在后续批次。第一期不使用真实税务凭据、不连接真实税务系统、不修改已有企业账套。

## 角色与 Git 管理

- Codex：需求与接口契约、基线审查、任务分配、复核测试、PR 创建及合并、冲突协调。
- pi：显式使用 `tokenhub/glm-5.3`，负责账务领域实现；后续负责规则与闭环验收。
- Claude Code：显式使用 `deepseek-v4.1-flash`，负责 MCP/API 与全国税务适配接口。
- 两个客户端均不得调用未获准模型、自动切换模型或擅自启动子 agent。运行日志保存在被忽略的 `.agent-runs/`。
- 每个并发任务使用独立 worktree 和 `codex/` 分支。员工只修改自己负责的文件，提交、推送与 PR 合并由管理者集中执行。
- 不在 main 开发，不强推，不删除既有成果。公共契约先写入任务单；同一文件的核心改动串行处理。
- PR 必须包含问题与结果、修改范围、测试结果和未完成项。验证必须使用临时数据库，禁止 `seed --force` 或触碰真实运行库。
- 保留原站 `catalog.json` 为证据；本地能力目录应单独维护，准确反映可用/未接入状态。

- 明细科目按已有编码体系汇总，避免父子重复统计；资产表、现金流、相关报表口径一致。无需宣称完整企业会计准则支持。

## 全国电子税务局接口约定

真实税务系统、区域和协议尚未逐一核实，第一期不写具体省份网址或假定统一全国协议。接口需要支持全国入口以及地区适配覆盖，明确地区未接入状态。

- 区域与能力：标准地区标识、适配器 ID、能力版本、支持的登录方式、支持查询资源、接入状态。
- 登录：发起登录、查询会话状态、提交人工验证响应、退出会话。状态包含未配置、待验证、已认证、过期、失败；不得绕过验证码/扫码/实名操作。
- 信息查询：当前身份/授权企业、企业基础资料、税种核定、申报状态等资源类型；适配器按地区公布实际支持项。
- 认证资料通过凭据引用或受控运行时注入，不把密码、验证码、Cookie、Token 写进 Git、日志、报表或普通查询响应。
- 区域、账套/企业、会话严格关联；不支持、未认证、会话失效返回结构化错误；真实适配器未配置时禁止模拟成功。
- 测试可注入完全本地的假适配器验证状态机，但不得把测试实现作为默认生产后端。

## 合并规则

先合并 BASE。CORE 与 MCP 分别测试和审查，合并前更新到最新 main 并重跑受影响测试；TAX 与 FLOW 在共同基线上并行。所有 PR 由管理者阅读实际 diff，核验测试输出与文件范围后 squash 合并，记录链接。没有通过或模型/权限受阻时记录真实状态，不宣称完成。
