## P1.5 · 报表闭环（当前优先级，2026-10-15）

用户目标：办税员账号登录 → 授权企业 / 账套 → 财务操作 → 出报表；**两类报表都要**（内部 3 表 + 余额表/明细账，以及税局申报格式）。前端展示次要。完整方案、依赖顺序、数据可得性门槛与验收场景见 [报表闭环补全方案](REPORT-CLOSURE-PLAN.md)。

| 顺序 | 工作包 | 状态 | 说明 |
|---|---|---|---|
| 1 | RC-0 `TAX-BROWSER-REVIEW` + `LOGIN-DATA-PROOF` | ⬜ 待派（首包） | 分两步：①新隔离工作区形成可核验快照（只复制源码 14 文件 / 补丁与基线，不复制 DB / 凭据 / 临时 profile / 日志），先复现旧草稿测试再在最新 main 整合复用必要改动；②用户本机真实登录验证数据链路与可得性；可合理统一为一个 ID |
| 2 | RC-1 登录会话 / 办税员 → 授权企业 → 账套关联 | ⬜ | 区分身份 / 授权企业 / 税局登记数据 / 本地账套明细；含实际账号 / 凭据入口、适配器与最少 UI；覆盖过期、验证码错误、二次验证、授权撤销、企业切换与串账 |
| 3 | RC-2 目标账套定向导入、数据落地与重试（幂等） | ⬜ | 旧 IMPORT-IDEMPOTENCY 在此归位；含标准 DTO 转换、完整性与映射预检、稳定业务键、最小恢复能力 |
| 4 | RC-3 财务流水线完整性 | ⬜ | 科目映射 / 期初 / 凭证 / 计提 / 结转 / 结账，并核实报表口径缺口 |
| 5 | RC-4 内部报表导出（3 表 + 余额表 / 明细账） | ⬜ | 可下载，不只是网页查看 |
| 6 | RC-5 税局申报格式导出 | ⬜ | 官方模板与要求**待官方核实**；可申报文件 ≠ 已提交 |
| 7 | RC-6 端到端联调与交付 | ⬜ | 以功能验收场景为准，不以 UI 页面数为完成指标 |

当前**真实接入数为 0**：尚无任何地区的真实税务适配器或已验证的真实登录；税局是否提供科目、期初、凭证、银行流水、发票**不可先行承诺**。

## P2 · 发票与申报（后期，自研或接第三方）

### 必须完成：全国电子税务局办税员登录与信息获取

> 排序说明（2026-10-15）：本节是 P2 长期目标；**当前优先是 P1.5 报表闭环**，其 RC-0 先做草稿审查与数据链路可行性（含真实登录验证与官方模板核实并行），再进入 RC-1 登录与账套关联。全国仍为长期目标，当前 0 接入。

第一期只交付统一适配器接口、31 省区市 + 5 计划单列市路由目录及契约测试，真实接入数为 0。**报表闭环 RC-0 第二步先选一个可授权联调地区做真实登录与数据可得性验证**，再由 RC-1 打通凭据引用、人工验证、授权企业选择、信息查询及退出，之后按地区分批扩展；每个地区分别记录协议核实、实际登录和取数验收。真实登录、凭据生命周期、超时/重试、会话清理和覆盖矩阵通过后才能标记该地区可用。不能以目录存在替代全国适配完成。

接口说明见 [TAX-INTEGRATION](TAX-INTEGRATION.md)。该目标为用户确认的必做项；实际账号与联调授权在该阶段另行落实。

| 项 | 说明 | 触点 |
|---|---|---|
| 发票采集 / 查验 | 对应 `invoice_collect` `invoice_file` `invoice.detail` | `agentTool()` 分支 |
| 开票 / 红冲 | `invoice_precheck` `tax_code` `issue` `red_*`；需税局或服务商通道 | 同上 |
| 全税种申报 | `declaration_query` `tax_declaration_query`；增值税/附加税/所得税/印花税 | 同上 |
| 个税申报 | `individual-income-tax-filing` 子智能体 | 同上 |
| 其余规则正文 | 记账与旧账导入本轮补齐；发票、企业申报、个税等仍待接入后完善 | Skill 文档 |

> 合规提示：开票与申报必须通过合法通道（电子税务局 / 持牌服务商），
> 相关能力不实现则继续返回 `not_implemented`。

## P3 · 本机化（单用户、多账套）

> 本项目只在本机单用户环境运行，可批量处理多个企业 / 账套；**不做** SaaS、多租户、租户权限平台或对外服务。以下均为本机实际需要。

| 项 | 说明 |
|---|---|
| 账套数据隔离 | 不同企业/账套数据不串号，账套维度校验前后一致（本机批量处理的前提） |
| 操作日志 / 审计留痕 | 凭证与批量任务等关键操作留痕，可追溯 |
| 备份与恢复 | 本机 SQLite 数据与导入批次的可控备份、恢复 |
| 凭据安全 | 只接受 `credentialRef` 引用，真实凭据不落 Git/日志/报表/响应；接真实税局前整改内存暂存（见 TAX-INTEGRATION） |
| 本机部署 | 一键启动脚本 + 进程守护 + 失败重启；本机单用户不需要反代/多租户部署 |
| 前端工程化 | 视需要演进现有零构建网页，不引入账户体系 |

对接有数云 API（可选）：仅在获得授权与凭据前提下复用，不作为多租户前提。
