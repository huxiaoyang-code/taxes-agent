# 本地 agent 执行，Codex 管理

## 何时使用

- 在本机进行项目开发、缺陷修复、测试、文档或 Skill 编写与维护时使用。
- 普通问答、资料查询、只读讨论不套用本流程，不劫持日常对话。
- 用户另有明确指示时，以用户指示为准。

## 角色边界

- **本地员工（pi / Claude Code）负责实施**：文件探索、代码 / 测试 / 文档 / Skill 的编写与修复，并在交付前自测。
- **Codex 负责管理**：任务拆解、建立隔离工作区、阅读实际 diff、运行验证命令、编写任务单与 PR 正文、执行 Git 与 PR 合并、安装已审查的 Skill。
- Codex **不直接补写业务代码、测试或交付文档**，即使是很小的修改也退回本地员工。
- 语义冲突、业务规则取舍交本地员工处理；Codex 执行 Git 并审核结果。
- 本地员工**禁止**自行 `commit` / `push` / `merge`；提交与合并只由管理者集中执行。
- 本地 agent 不可用时，先在**当前已授权的客户端、服务与已核实获准模型**之间诊断、重试或切换，不重复申请已有授权；切换前先核实旧进程与交接，避免重复启动或覆盖未完成成果。
- 持续不可用时，保留任务、分支与交接现场并报告阻塞原因；只有需要改变角色或扩大授权时才询问用户。**不得仅因新会话就推断任务已丢失**，应先读交接恢复。Codex **不得静默亲自开发**接管。

## 本地员工要求

- 遵守任务单给出的工作目录、文件所有权、接口契约、验收条件和数据边界。
- 完成任务必需的上下文由任务单提供；不把无关历史日志灌入任务包。
- 自测后才交付，并说明实际变更与失败路径；不得删改旧断言或伪造成功。

## 模型约束

- 本地员工只允许 GLM 5.3 或 DeepSeek V4.1 Flash；主模型与回退模型都必须显式锁定。
- 启动前通过本地帮助、模型清单或非敏感配置**核实模型 ID 及其映射**；不猜测 ID，不把名称相近的版本当作允许模型。
- 不得使用其他模型或启动子 agent（含规划 / 回退模型）。核不实或不可保证时停止该本地调用。
- 本约束只约束被调用的本地 agent；**不声称改变 Codex 会话自身的模型**。

## 授权与数据边界

- 先从当前会话与项目记录核实已有授权，只询问确实缺失的必要范围；**不要发送固定授权清单**要求用户逐项确认。
- 模型 ID、工具绝对路径等属于管理者可读可核实的检查项，由管理者按本机实际核实，不要求用户提供。
- 未获自动合并授权不阻碍在已有授权范围内实现、测试与准备可审查 PR；合并前再核实一次合并授权。
- 用户已明确授予的授权不必反复询问；但通用 Skill **不复制**任何项目的源码外传或自动合并授权。
- 新项目必须核对当时的授权范围与服务；不从本 Skill 推导外传授权。
- 遵守任务隔离；真实账套数据与税务凭据不得发送到模型服务，开发所需源码 / 任务说明 / 测试错误只按项目当时授权范围外发；不得用本地 agent 绕过沙箱或审批。
- 客户端在本机运行不等于模型离线；不要把凭据或无关敏感内容放进提示词或输出日志。
- 权限与工具范围要和实际授权匹配，不是拿工具限制去绕沙箱。

## 任务到 PR

- 以项目适用规则建立**独立 worktree 与分支**；本用户默认 `codex/` 前缀，具体遵守所在仓库约定。每个并发任务明确文件所有权；禁止在 main 上开发、强推或覆写他人未提交成果。
- 本地员工不自行 `commit` / `push` / `merge`。管理者先阅读实际 diff 并运行相关测试、核对最新基线；通过后由管理者提交，再比对待合并 head 的内容与已验证内容一致，锁定该已验证 head 才推送、开 PR，并按已有授权合并。
- 测试后若 main 有新提交影响当前接口或行为，应把最新基线纳入当前分支，重新审查并重跑受影响测试；影响面大时按项目规则跑全套。
- 审查通过后锁定已验证的 head SHA；**已有自动合并授权不因基线更新失效，不重复询问**。
- 审查未通过退回本地员工修复；**没有明确授权时，不得由本 Skill 推导自动合并**。
- PR 正文写明问题、结果、验证方式与限制。合并并记录交接后，关闭本地员工会话，用新进程 / 新会话进入下一部分。

## 交接与会话重置

- 每部分按「验收 + PR 合并 + 交接」完成后，关闭该部分的本地员工会话。
- 下一部分使用**新进程、新会话**：pi 用 `--no-session`，Claude Code 用 `--no-session-persistence`，不使用 resume / continue。
- 关闭会话不能代替检查退出码，也不得遗留重复执行的员工进程。
- 可以核查文件与 Git 事实；**不得宣称已强制清空 Codex 对话**。
- Windows 具体启动命令与占位路径见 [references/windows-launch.md](references/windows-launch.md)，路径须先核实。
