# 用宿主读取原件

从当前工作区的 `.finance/business-session.json` 取绑定的 `sourceRoot` 和 `auditDir`。没有会话绑定的账前调查用 `.finance/host.json` 中的 `mcpEnv.FINANCE_SOURCE_ROOT` 与 `auditDir`。以实际授权为界。用宿主已有的文件、脚本或表格能力按需调查，生成的整理件放 `auditDir/agent-materials`。保留原件和原始文件字节。

## 格式、编码和字义

自行选择当前本机能运行的读取方式。源格式声明和扩展名可用来初判，需用几处可定位的实际内容验证。旧二进制 XLS 声明代码页与实际文本不符时，可在本机对同一字节试候选编码。用相互独立的表头、科目或单位、日期和金额列交叉判断，记录采用的编码及依据。资料存在 OCR、公式缓存、多个可能含义或实读缺口时，保留对应字段的不确定性。取少量实际需要的单元格、记录或文档片段，完整原文、数据表和诊断细节留在本机授权范围内。

## 整理为可追溯的本机观察

1. 按业务查当前 `finance_record_contract({recordType:"baseline"})` 或 `finance_record_contract({recordType:"prebook"})` 返回的字段与结构。按实际模板选择原件、观察值和业务解释。
2. 记每份采用原件在获准范围内的绝对路径和实际 SHA-256。给值附原始定位。表用从 0 起的工作表序号（可省默认首表）及从 1 起的行列，JSON 用实际指针，PDF／文本用从 1 起的页行号。需要字符区间时起点从 0 起，末端不含。
3. 独立记录主体身份与依据，区分企业、销方、购方。只有页首或表头能确认时，可以记录实际文件级主体。同源多个主体按实际记录划分。结构化企业原件自身含 `enterpriseKey` 时可附其实际观察值及位置，由已绑定账套核对。相同业务按实际合同号或可核业务号衔接。历史记录保留同源的期间、业务号和借贷位置，缺少实际日日期时保留月粒度。
4. 基线产物使用 `finance-baseline-observations/1`。用 `records` 清楚表达同一份原件中实际关联的业务对象及字段，另用 `historicalRows` 记录必要历史。若需要补充取数方法，记录采用的读取器、版本和编码。写到审计根 `agent-materials` 的 JSON 中，向 `finance_baseline_materials({target,inputPath})` 提交实际绝对路径。

MCP 校验整理件结构、目标、实际原件摘要及来源位置的声明形式。返回及持久证据标识 Agent 观察或基于观察的推断。历史处理结论还需要同业务的独立材料和适用条件。无历史证据、账套范围相冲突、原件已变或联结无法确认时，说明影响和未核事项。保留已确认分支。
