# 生成企业短业务基线

企业基线是针对特定企业及有效期间，从已核实资料中提炼的少量可执行做账原则。它说明采用的准则和方法、税会所属期、当期／分期／资本化边界、关键税务选择及可比税负参考。同等条件下沿用；条件变化或出现冲突时核实相关原则，明细和依据按需取回。它不是业务分类目录、凭证模板、明细台账或旧脚本清单。

## 从真实资料生成，再处理本期

1. **绑定并核身份。** 核实当前授权、实际账库、企业、账套、本期和资料根；用已有账套的真实 ID，不选第一家或凭相似名称推断。工作区绑定与本次目标须一致。未建账时可先做独立资料核对，不能为读基线伪建账套；跨企业不复用原则或资料。
2. **先查有效短基线。** 调用 `finance_baseline_read({target:{accountSetId,period}})`。`ready` 且本期条件未变时直接沿用，按 [本期取数与计算](references/materials-and-save.md#按短基线处理本期的本机取数) 读安全对象结构并本机计算，不重建基线或重翻全部候选／facts。`needs_generation`、`needs_review`、`stale` 或超有效期时调查受影响范围；目录 prepare、方法候选、一次计算成功均不表示已生成基线。
3. **实读主要业务与历史。** 按 [材料与保存合同](references/materials-and-save.md) 优先调用 `finance_baseline_materials({target,extractKnownFields:true})`，有界发现并批读当前范围已核主体且有已知语义的原件。按当前返回的 `pagination.next.arguments` 看候选余页，`sourceDiscovery.next.arguments` 接续批次；实际页长可收缩，不能手算 offset。核实际账套、代表性历史、主要合同／底稿及历史申报的完整字段组和同业务关系。未读页／未调查的相关范围先补查，不能称客户缺资料。批次游标继承已读依据，独立读取的相关引用仍须保留；子集重读不替代此前依据。用户供基础资料，Agent 整理参数，不依赖预选方法／脚本或重算全部历史账。
4. **核事实、范围和仍缺什么。** 结合 `principleSupport` 的实际支持、条件及适用期规则提炼重要结论，不自动全选。同业务的收入与支出方向须区分，不能仅因 `when` 相同认定分类冲突。本期仍须核条件，不等于已支持的条件原则 `policy_unverified`；规则时效或适用性未核时，先用 `finance_rules` 补查，仍未知则留准确缺口。目录未选项的主体状态不能扩散为已选材料的缺口，另一工具授权受限也不反证已有材料支持无效。缺支持先核字段组、分页和历史关联，补查后仍无依据、冲突或需真实业务决定才留未决。适用且有据的普通原则可保存，仍不等于人审。历史金额／科目不证明算法，历史错误不固化；真实资料仅经获准投影和本机可信界面核验，不用宿主 Read／OCR／SQL／脚本绕过隐私边界。
5. **核少量可比税负。** 从实际历史申报、底稿和缴款证据取得同口径汇总，保留对应税费材料引用；之前某次出现税负，不等于最后一个引用包含它。`coverage` 的未纳入不证明另有原件或该税适用；核当前任务和实有资料后可按已核范围完成，不为通用 `nextSteps` 凑两税或凭空转人工待核。已读／已知相关税料仍须合并，未知不补零，不按历史区间倒挤本期业务。
6. **核完整依据后保存。** 批次游标已继承前批依据；另行独立读取过用于结论、税负或必要缺口的材料，则显式合并这些成功 `materialRefs`，不能只留最后一次子集。核当前闭包的 `coverage`、重要支持及税费，再自主选重要 `supportRef`，用 `finance_baseline_save` 的 `principles:[{supportRef}]` 保存版本与适用期，不自动全选。最多24个语义项仍合并为最多8条／600个Unicode字符，可少于5条、不凑数。重要未决最多3项，不掩盖税费／主要业务遗漏或把未完成调查包装成人审。自由文字、`verified:true` 或模型自述不证明核实／批准。
7. **回读，确认没有漏掉已核内容。** 按实际 `kind/value/when/allocationBasis` 对照重要分支与短文，不能因种类或 value 已出现就认为另一适用条件已覆盖；用途归类与费用期间也不互相代替。结合分支提示核遗漏，同条件同处理的同义支持可去重，不为清空提示全选；状态、版本和未决须有实际依据。漏引用／未翻页导致丢失的内容应补读、合并并修正，不能在报告里补写后宣布完成。完成后按 [凭证编制](../journal-entry/SKILL.md)、[税费复核](../tax-review/SKILL.md) 或 [整期入口](../tax-period/SKILL.md) 处理本期；真实金额计算走 [本机取数路径](references/materials-and-save.md#按短基线处理本期的本机取数)，不回显原值。余额／合同进度不塞进基线，正式写账保持原审核与防重复控制。

## 结论要能指导做账

按资料支持的范围覆盖：实际会计准则；具体业务归主营／其他收入或按实际用途归集费用，存货成本计价；收入／费用确认所属期；销项义务与进项用途／确认所属期；当期费用、分期摊销与资本化边界；关键且仍有效的税务选择。行业标签不能代替业务归类，同一企业不同业务条件可能适用不同原则，不由一个样本推成全企业规则。原则应给处理结论和必要条件，例如确认时点或费用受益期间；不写“请检查收入”“有待考虑成本”充数。不在本技能预置税率、优惠资格或企业结论，实际规则按需通过 `finance_rules` 或已核官方原文确认适用期间及条件。

历史税负须分税种、应纳／实缴、所属期／缴款期、本期／累计。可比销售额与税额均有证据时，增值税区间按 **合计同口径税额 ÷ 合计可比不含税销售额** 加权，不平均月度百分比，不把银行缴税总额当所属期应纳。所得税累计预缴或年度结果单列，不重复累加多个累计值，不用利润率或增值税负替代所得税口径。仅有累计VAT而无法形成可比区间时保留缺口，不静默 `ready`；来源不支持的范围不生成精确区间。

## 沿用、变化与报告

同条件沿用现有版本；普通业务、新金额或新凭证由原业务工具留痕，不追加基线。会计政策、长期处理原则或有效税务选择改变时才保存新版本；来源修订、缺失、不可访问、范围过期和实际业务冲突按返回状态分别核受影响规则，不通过换根或 prepare 洗掉已知失效。旧版本留档，不重复常驻注入。具体对象的旧方法、案例和脚本仍可按 [企业记忆参考](../shared/references/business-memory.md) 按需查询，不要求先登记事实、维护 DAG 或第二套业务台账。

按 [报告顺序](../shared/references/reporting.md) 交付本期金额与异常、实际采用的短原则及必要依据；另说明生成未完成或仍影响本期的少量重要缺口。保存和 `ready` 不代表会计审定、政策适用已获人审、正式申报或缴款完成。
