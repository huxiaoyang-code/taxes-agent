# 完整账期与中文复核交付

按企业委托核对完整账期，沿用官方财务报表、凭证准备和余额调节方法。Agent根据原件、适用规则与交付用途，自主选择 Python、电子表格公式或已有计算器，生成可复算的派生账簿与报表；系统记录读取、计算和结果，不建立额外任务DAG。正式写入原生账库时，仍使用实际业务工具的授权、期间及防重复控制。

## 原件与字段

使用获准的文档读取入口查看中文表头、期间、数量与金额单位及实际数据行。读取时自动保存实读版本和原结构；后续调用业务工具时再保存原件字段如何成为参数，两者是不同记录时点。没有记录初读时明确缺少记录，不能用传参前补读冒充。客户只提供正常业务资料，不要求客户预先编写分录、结果或工具内部模板。

用中文记录业务事项、处理方法、规则来源及采用理由；参数详情保留原始表头、实际行列/页码、原值、单位及业务语义，与采用值、计算表达式并排可查。固定求和、差额、乘积与业务选取须说明依据；数值相同不证明业务语义正确。使用原生工具时可按其合同携带`businessEvidence`和`mappings`，这些技术字段不是 Python/表格计算的先决条件。现金流按实际收付、核销证据与适用准则分类，不能把所有对方科目净额直接冒称完整现金流量表。

## 计算、凭证和账库

先确认采用《小企业会计准则》还是《企业会计准则》，仅按需查本次业务涉及的规则、来源、有效期与适用条件。规则服务和已有税费计算器可辅助核对；也可据已核规则用 Python 或表格计算税费、成本、折旧、结转和报表。保留实际公式/脚本、输入、输出和核对结果；可用`finance_calculation_run`执行并由系统记录，入口及边界见[计算连接](connectors.md)。未解决的规则继续标为未解决，不以工具默认值代替规则判断；不能把模型计算称作原生引擎已经核账。CSV整理和派生合计都不是新原件。

原始业务计算可选`finance_workpaper`；原生草稿、计算生成的电子账簿与数据库内总账须注明各自状态。用户确认采用的电子账簿可直接交付使用；是否审核、批准或已写入某账库按实际证据判断，不以生成者或数据库导入作为账表交付资格。复用原生逐笔草稿或FIFO明细时可按`finance_workpaper_details`合同分页查询。接口缺字段或拒绝输入只说明该路径的限制，不证明企业缺少相应事实；按原件可支持的精度继续计算并披露工具限制。账套、期初、科目、凭证、资产卡片或结账确需写入原生账库时使用正常业务工具，不伪造批准。若账簿与计算底稿不同，两者并列调查，不以平衡差额造凭证。

原生计算金额使用工具支持的结果引用；自主计算保留脚本/公式与原件定位。均不得复制成新文件冒充原件。期初盘点未核时，可以按有来源的账面期初继续推算，明确“以账面期初为条件、盘点未核”及影响，不能声称盘点通过。认证资料只有月份时保留月份，不猜具体日。逐人个人社保与住房公积金合计若能支持本次扣除用途可直接使用，不能宣称细分已知或据此核单位负担、分项缴款。

## 中文账表

按委托形成账簿及四表：科目余额表、利润表、资产负债表和现金流量表，保留可复算公式/脚本。最终以系统生成的固定中文账务复核卡片作为一个入口，工作簿可作为明细附件；不要求模型再编写最终 HTML 或重复规则说明。原生账库已具备资料时可选`finance_quarter_review`导出；自主计算无需原生季度导出或bundle才能交付。科目余额表核期初、逐月借贷发生与期末，并区分结转前后；利润表核季度和累计；资产负债表核期末与重分类；现金流核真实经营/投资/筹资收付及期初期末现金。现金流项目和价税列报按适用准则与事实核实，不硬套某案例口径。缺资料、未过账、规则未解决或未分类收付保留中文状态和影响，能算的部分照常产出，不用利润倒推现金或调整项强行配平。

按[固定卡片合同](connectors.md#固定账务复核卡片)提供明确结构的账务结果，系统在计算结束后读取对应版本并渲染，不替 Agent 选择业务流程。未支持的文件格式或缺失映射保留缺口，不能声称已自动取数。卡片默认看余额、银行与现金；需要时沿金额→凭证/计算→规则→工具→输入原件追溯，见[报告规范](reporting.md)。原件表头、选中数据行/值与实际参数保存在可检索记录中，不另铺三组重复索引。HTML、XLSX及复核文字全部中文；代码标识、真实文件名和来源标题可保留原文。工作簿可以直接包含公式或引用可复算脚本，也可以呈现原生结果；保留期间、币种、金额单位、未知与零。逐张检查中文、数字/表头裁切及金额到原件的追溯。前台用正常中文名称和业务编号，底层调用、路径与原件索引留在深入核查层。输出存独立运行目录，原件不改；记录失败如实披露，不冒称已留存，也不抹去已经完成的计算。
