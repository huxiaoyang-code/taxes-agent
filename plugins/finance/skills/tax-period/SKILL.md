# 企业整期账税与申报准备

适用于“完成这家企业本期账税”“把本季申报准备好”“接上次补件继续”等整期目标。任务是交付有来源的账表、税费依据、合法可行方案与明确未完事项，不以算出一项税额或生成报告等同整期完成。当前没有税局正式申报、缴款或开票接入。

先核实企业、账套、期间、任务边界与资料授权；同一操作者可处理多家企业，每家单独账套。单项查询、税额试算或凭证请求直接进入相关技能，不扩张为整期流程。原件、账库和凭据仅在本次获准的本机通道处理，不以“本机工具”推定允许外发；模型只接收获准投影与引用。

核实账套和月份，沿用其 `MEMORY.md` 中当期适用的口径。缺少或变化的条目按[账套记忆](../company-baseline/SKILL.md)调查核实。整期完成须核本期实际账表、来源和未决事项。

本期出现新业务、优惠到期、地区或适用期间变化时，用 `finance_rules` 搜公开政策词并打开相关官方原文，按[官方政策核查](../tax-review/references/official-policy.md)记录本期采用的条款和适用条件。

处理“做完本月账”时，获取本期进销项、历史锁定与客户口径后，按[逐票抵扣与方案比较](../tax-review/references/vat-planning.md)提出并复算选择，按[税款现金简报](../tax-review/references/tax-cash-brief.md)说明应纳与实际或预计付款，再按[当期／全年会计交接](../tax-review/references/tax-organizer.md)把账表、税费、原票和回执勾稽。按身份、资料和任务范围进入适用分支。

整期做账遇到账实差异，进入[账目核对](../reconciliation/SKILL.md)，从独立原件核对到账套分录。委托范围内自行更正有据的错账，读回凭证和受影响的往来、账表再交付。仅测算或出报表的任务沿用账载数，列示测算调整。接续时拿上次已核的差异、已确认口径与本次产物逐项对照。

## 按任务选择阶段

需要安排月结顺序或梳理年末未决事项时，查[月结与年度核对](references/close-management.md)，确认哪些工作已有资料、哪些依赖上一步的实际结果。

从当前实际产物确定起点，执行本次目标需要的阶段；已有有效结果可复用，资料变化则重算受影响部分。下面是业务判断提示，不是新增任务 DAG、事实登记或状态库。客户提供基础资料，Agent 负责整理、计算和判断，不让客户先填内部 JSON、编凭证或给最终税额。

把用户本次明确要求逐项映射到实际交付与完成条件，不能只按五阶段标题宣称完成。季度或年度委托按实际所需月份、申报频次及税种检查覆盖；`finance_period_review.target.period` 是单月，只复查该月记录，须分别核对所需月份，不能用末月记录或累计金额冒充全季/全年覆盖。月度、季度和年度结果状态分开，缺月保留对期初承接、利润、累计税基和报表的影响；年度任务还需全年调整与亏损等年度条件，不能把季度预缴当年度汇算完成。

复工时使用原调用号核对既有底稿。年度工具绑定同账套十二月后，`finance_period_review` 可读回年度已记金额、来源版本和受影响月份；用底稿引用在新进程逐页核对明细。覆盖月份和真实交付文件决定年度任务是否完成。

## 交付前主动检查

在已绑定的整期工作区，把本版实际文件放进 `outputs/`，用 `finance_period_review({delivery:{}})` 送审。程序按同版账库、原件和文件核资产负债表、进销存及增值税。遇到 `blocked`，按 `delivery:{version,issue}` 展开一类证据。接手方可用 `delivery:{role:"bookkeeper"}`（或 `product`、`accountant`）取自己的返工项，修正后重新送审。

`awaiting_independent_review` 时，只把回执中的版号交给独立复核会话。该会话使用同一工具的 `delivery:{reviewVersion:版号}` 重新取数。收到 `ready_for_accountant` 后，将返回的版本目录交会计，并说明其他委托项目的实际覆盖。需要核原文时，用 `delivery:{version,evidence:true}` 打开同版的本机取证目录。

在已绑定的工作区交付科目余额核对表时，把实际导出放在 `outputs/`，余额 CSV 文件名带所属期。产品导出的原生科目余额表可直接复核元数据、借贷栏、本年累计、总计和试算平衡。会计自制表的表头包含科目编码、期初方向、期初余额、本期借方、本期贷方、期末方向、期末余额；每个有余额或发生额的科目逐行列示，附按类别计算的小计。交接 Markdown 写明本月与次月。对于需要核实的事项，在同一行注明“已解释”或“待办”、相对于已绑定原件目录的文件路径和业务标识。

以 `finance_period_review` 的 `target` 和 `deliveryCheck:{balanceFile,handoffFile,references}` 复算。每条原件引用含 `file`、从 1 开始的 `line`、可唯一定位的 `id` 和处置 `disposition`（`explained` 或 `outstanding`）。交易标识使用原件完整字段值。引用行有金额主张时，给该引用附 `amounts:[{column,value}]`，从原 CSV 表头选对应金额列。确实缺原件的具名事项可列 `missingMaterials`，写明业务标识 `id`、受影响月份 `period` 和具体影响 `impact`，在交接原文同一行注明待办。`needs_repair` 时按返回的行号、字段和账库金额改正，重新读回；`partial` 和 `needs_materials` 要在交接说明剩余影响。

按真实业务复查可扣除支出及凭证条件、进项用途与抵扣/留抵、小型微利等优惠资格、可弥补亏损及有效期、预缴余额、可依法选择的处理方法。先以事实和有效规则筛出可行选项；无备选就说明原因，不强造方案。不能按目标税负补造成本、倒推发票、改变既定交易或为了利润转正随意改跨期。详细比较与租赁分口径见 [方案参考](references/planning-cash.md)。

## 中断、补件与更正

从同企业、账套、期间的实际账表、原件和送审版本恢复。查询既有调用记录时使用下列历史记录入口。记录缺失、范围不匹配、执行未结束及业务未证实的部分保留未知。首次无账库的账前任务可直接核对资料。

有账套时读取当前工具合同后传 `target:{accountSetId,period}`，可用 `callIds` 限定已知记录，或用 `offset` / `limit` 分页，两种选择互斥；ID 来自实际账套查询，期间采用工具支持的月度值。仅有账前或自主计算记录时，可单独传 `unboundCalls:{callIds:[实际调用编号]}`，与 target、顶层 callIds 及分页互斥。该分支 `mode=unbound_call_review`、`scopeVerified=false`，只逐条检查已知执行记录，不能据此声称已核企业身份或汇总整期结果。没有旧编号就从现有实际产物调查，不猜编号或任意日志路径。

收到补件后核对版本和覆盖范围，按相关技能重算受影响分支，并核实旧问询是否真正解决。老板说明、上次模型说“完成”、新一次调用成功均不能自动关闭旧问题。写入结果未知时查询原操作，禁止换 ID 盲目重做。交付报告沿用 [报告顺序](../shared/references/reporting.md)，在现有报告中列接续入口及未完项，不另建重复状态表。
