# 在本机银行工作台导入、匹配和保存调节

核对原件和已入账分录的委托可以直接用[对账技能](../SKILL.md)完成。中途追加保存匹配时，沿用已核实的流水和凭证依据，先查所选账户已有批次和匹配状态。

在“本机银行流水与余额调节”选定账套、人民币账户、期间和当前操作。各工具使用同账套、对应操作签发的 `accountSetId` 和 `draftRef`。工作台保留 CSV、凭证候选及具体行。每次动作以真实回执为准。

| 办理事项 | 用途与完成依据 |
|---|---|
| 核对账户与导入历史 | `bank_accounts` 查登记账户，确需新增时在本机确认，用 `bank_account_register` 登记。用 `bank_batches` 核已导入批次，防止重复。 |
| 导入流水 | 选 CSV、用途及列映射，用 `bank_import_preview` 核日期、收支、金额与重复行。本机确认预检后，以对应的导入引用调用 `bank_import`，读回批次结果。用 `bank_ambiguities` 查疑似重复行；仅按真实选择和理由调用 `bank_ambiguity_resolve`。 |
| 保存或撤销匹配 | 用 `bank_transactions` 核导入状态，`bank_candidates` 查所选流水的凭证候选。在工作台按原件逐项核对日期、金额、对方及分录并选定候选，确认后用 `bank_confirm` 保存。用 `bank_matches` 核回执和状态。有撤销委托时用 `bank_cancel` 办理。 |
| 保存余额调节 | 核实际结单覆盖期、期初及截止余额，确认后用 `bank_reconcile` 保存，读回调节差额。用 `bank_status` 核进度，`bank_audit` 查本账户操作历史。 |

查询 `bank_transactions`、`bank_candidates`、`bank_matches` 和 `bank_status` 时会重验匹配并记录失效，按本次银行业务委托使用。普通只读核账使用原件、凭证和科目明细。

本会话尚未取得所需草稿时，交代需要在本机选定的账户、行和操作，继续其他已能完成的核对。引用过期或选择发生变化时，从工作台重核该对象并取新引用；写入结果未知时先核原操作、已保存批次或匹配，避免重复提交。按导入、确认、撤销及保存各自的实际状态交付。
